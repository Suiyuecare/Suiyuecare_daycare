## 使用者體驗原則

- 照服員：自己的今日當班個案 → 下一件工作 → 保存確認；選定個案後延續日期、班別及個案，不重選。
- 護理／個管／專業人員：先看待核對、待簽署、風險與有效照顧依據；不讓規則候選冒充醫囑。
- 主管：缺人、缺資料、逾期、衝突與責任人；每個問題都有補正入口，不只有工程狀態。
- 財務：待開帳、待收款、待申報、待對帳；不重建第二套 Finance。
- 老闆：只呈現該店個案出缺勤人數、Finance 收入與支出，不擴增人資／薪資／投資報酬儀表板。
- 家屬：只呈現自己獲授權個案的已核准公開資料與能處理的事項。
- 沿用現有 Finance 配色、frame 與模組載入動畫。桌機重比較、手機重單一任務；每一步只有一個主要動作。
- 工程資訊收在管理詳情；風險、未保存、無權限及不可逆操作不得隱藏。

## 第二部分：對應驗收標準

### 共通門檻

1. 真正保存：界面操作 → API → 資料庫 → 重整或第二裝置讀回同一版本。只出現成功訊息、mock成功或 HTTP200 不算。
2. 隔離：代表角色×頁面×動作×機構／分支／個案／欄位正反測試；直接API／RPC／改網址亦拒絕越權，外洩0。停用員工5分鐘內既有會話不可繼續讀寫。
3. 不重複：同一操作連點／重送10次，只產生1份有效業務結果；同鍵不同內容拒絕。兩人同時修改同一基準版本時不靜默覆寫。
4. 不冒充完成：本機草稿、伺服器草稿、待簽署、已簽署、送出、送達、已讀、已確認按各領域分開；失敗或逾時保留內容及原操作識別。
5. 留歷程：查閱／新增／修改／匯出／列印／簽署／更正／規則與權限變更可查責任人、時間、版本；已簽署內容不直接改刪。日誌不含明文個資、token或附件。
6. 好操作：選定個案後高頻任務原則上不超過3次主要操作（不省略必要輸入與確認）；至少3位代表性前線使用者不經工程提示測試，90%以上一般快速紀錄於60秒內完成。
7. 跨裝置：390px手機、平板、1440px桌機無整頁橫向溢位；觸控至少44px、輸入字級至少16px；鍵盤、焦點返回、錯誤提示、螢幕閱讀器及WCAG2.2AA自動與人工驗收。
8. 完整狀態：載入、空資料、無權限、錯誤、逾時、離線、過期與重試；沒有資料不等於正常，未觀察／不適用／實際0分開。
9. 一致：Asia/Taipei日期，畫面、明細、PDF、匯出與申報同一快照；統計可追到適用來源，來源未準備好不算已完成。
10. 完成證據：每頁保存角色、前置資料、操作、預期、實際結果、資料重讀、拒絕與重送案例、截圖／紀錄及業務簽核人。89個路由能開或匿名被擋，不是89頁功能驗收。

### Google 驗證政策變更的特別門檻

一般作業改為受控公司Google會話；不是把Google登入偽裝為Supabase AAL2。高風險簽署／大量匯出／權限調整／申報須另完成近期身分證據、同意內容與適用雙人覆核設計。優先驗證可否以可信Google重新認證證據做到不另裝驗證器；只再選帳號、刷新token或勾選同意不算。

先做獨立技術驗證：驗證簽名、issuer、audience、nonce、穩定subject、可信auth_time、時限與同一操作綁定；確認透過現有Supabase登入鏈是否可取得可靠證據。若拿不到，提出替代方式與影響請負責人確認；未通過前不默默取消高風險保護，也不自動新增驗證器要求。此政策須同步更新前端、API、RPC／RLS、稽核語意與測試。

依據：[Supabase驗證等級](https://supabase.com/docs/guides/auth/auth-mfa)、[Google OpenID Connect身分與auth_time](https://developers.google.com/identity/openid-connect/reference)。供應商文件不是本機構法律／電子簽章適用性核准。
