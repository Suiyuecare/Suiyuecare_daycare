## 結論

目前是可執行的 R0／R1 工程基線與首批垂直切片，**不是可直接取代既有系統的正式版本**。

- 11 模組、89 頁皆有穩定路由與 catalog 驗收條文。

逐頁狀態、現有證據與不得推論事項以 [R0_PAGE_ACCEPTANCE_MATRIX.md](./R0_PAGE_ACCEPTANCE_MATRIX.md) 為唯一明細。

## 已收斂的核心邊界

- 所有正式 API 從伺服器 TenantContext 綁定機構、分支、使用者與權限；瀏覽器不能自行指定 actor 或擴大範圍。
- 所有新專用寫入使用 actor-scoped 冪等鍵、嚴格 request／response schema、結構化錯誤及資料庫交易；相同鍵不同內容被拒絕。
- 所有瀏覽器網路呼叫已集中使用有界逾時：一般互動 20 秒、HTML 上傳／重解析 60 秒、登出清理 10 秒。寫入逾時只表示結果未知，畫面保留內容與原冪等鍵供精確重試，不會自行宣稱失敗或建立新操作。
- 簽署、核准、權限擴張、用藥與通知建立等高風險動作使用當下 AAL2；需要近期驗證者另保存同 session、15 分鐘內的不可變 challenge 證據。
- 已簽署或已承諾的紀錄採 append-only 版本／更正鏈，不允許一般瀏覽器直接 `UPDATE` 或 `DELETE`。
- 正式資料讀取使用有界、可稽核 projection；截斷時涉及完整名單的寫入會 fail closed，不以部分清單冒充完整結果。
- 家屬只可經個案、關係、資料類別與期限同意的白名單摘要 RPC 讀取；健康與用藥公開模型未完成前維持拒絕。
- HTML 只做靜態解析，不執行 JavaScript、表單、redirect 或外部請求；正式 approval 目前只凍結 staging，不能稱為已匯入業務表。
- 離線只允許三類白名單草稿；以機構、分支、使用者命名空間與 AES-GCM 隔離，登出清除 IndexedDB。正式同步 consumer 與 60 秒 SLO 尚未完成。
- 通知文案在 API 與資料庫均阻擋身分／健康敏感內容。#45 只建立員工站內 `queued` delivery，絕不把 queued 顯示為 sent、delivered 或 read。
