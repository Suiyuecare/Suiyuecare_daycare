# 日照系統視覺與低學習成本改造基線

日期：2026-09-28。此文件是分批實作與驗收清單，不把局部改動、合成展示或路由可開啟視為 89 頁正式上線。沿用 Finance 的外框、字型、色彩、間距與控制樣式，不另造視覺品牌。

## 現場體驗原則

1. 登入後先看到自己今天的個案、尚待處理與下一個可執行動作；主管看到例外與待核對，管理與工程資訊進專屬頁。
2. 一個畫面只突出一個主要動作。個案、日期、班別在相鄰工作延續；若某動作不具班別意義，不能假裝按班完成。
3. 先呈現狀態與下一步；公式、來源雜湊、版本與稽核資訊預設收起，但保留可查入口。空資料、尚未排班、無權限及載入失敗必須明顯不同。
4. 表單採分段、即時欄位錯誤、首錯聚焦與可恢復草稿；送出結果不明時固定原對象、原內容與原鍵，不能以「再新增」代替重試。
5. 敏感資料與不可逆操作先說清對象及後果，再確認。不能把草稿、候選、已送出或伺服器紀錄混稱為完成。

## 分批路線與可量測驗收

| 批次 | 畫面 | 驗收 |
|---|---|---|
| 1 今日工作與相鄰紀錄 | 首頁、今日名單、出勤、量測、日誌 | 只列授權且已確認的班別；單案主要任務原則上三次主要操作內完成；雙班不得誤存全日；查詢、卡片及明細口徑一致 |
| 2 評估與收案 | 評估入口、A／B／C／D、九份題目式量表、CMS 建檔 | 選案後表單明確鎖定同一人；未知／失權選案零寫入；逐題填寫有進度、缺題及保存狀態；候選與正式量表不混淆 |
| 3 主管與機構管理 | 分工、開通、資格、異常、申報準備 | 先看缺什麼與誰處理；批次操作預覽影響筆數及對象；失敗逐筆可回查，不顯示假成功 |
| 4 家屬與老闆 | 家屬 PWA、單店出缺勤、Finance 收支入口 | 只顯示被授權個案與該店資料；數字有期間、更新時間、來源及下鑽；連線失敗與 0 分開 |

每批均須有合成 Chrome、權限矩陣、錯誤／逾時、冪等與回讀驗收。正式個資、Google 員工登入、hosted Supabase RLS、掃毒與封存、備份還原、申報週期、50 人並行及 `docs/PRODUCTION_GATES.md` 必須另以真環境證據通過；本文件不替代。

## 現場易用性驗收

找至少 2 位照服員，及護理、社工、主任、經營者各 1 位首次接觸新版的真人，用各自授權的測試資料做觀察。不得由設計者口頭指路：至少 90% 的指定任務能自行完成；選錯個案／錯班別後仍送出為 0；高頻照顧任務從選案至儲存的中位數不超過 2 分鐘；每個人都能分清「草稿、待簽、完成、無權限、資料載入失敗」。記錄點擊數、用時與卡住位置，未達標就修版再測，不以問卷滿意度取代操作結果。
