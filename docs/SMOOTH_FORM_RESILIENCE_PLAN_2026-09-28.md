# 常用表單的順手操作計畫

日期：2026-09-28。狀態：本機實作與驗收完成；尚未發布，也不代表正式營運驗收。

## 目標與範圍

讓員工在個案建檔／異動、個案查詢及每日紀錄時，遇到缺漏或網路錯誤仍能清楚知道下一步，不遺失已填內容。沿用 `DESIGN.md` 的 Finance 外框、字型、色彩、控制高度及既有欄位元件；不改權限、法定表單、臨床規則、API、資料庫或申報口徑。

本輪以 `src/components/clients` 中五個個案工作區及 `core-daily-workspace`、`operational-workspace` 為完整切片；另修正今日清單的搜尋保留與評估入口的選案斷點。只修正這些工作流程，其他頁面維持原狀，不宣稱 89 頁同時完成。

## 現場問題與處理

| 現場問題 | 修改方式 | 驗收 |
|---|---|---|
| 必填欄位跳出瀏覽器原生泡泡，語氣與位置不一致 | 表單由系統顯示短句錯誤，保留現有伺服器驗證 | 缺值／錯格式不發出寫入；欄位旁有中文提示，首錯可聚焦 |
| 修改或異動送出失敗後要重填 | 同頁保留非敏感輸入與原操作脈絡，錯誤不覆蓋使用者內容 | 失敗後原值仍在；既有冪等、結果不明與寫入鎖不被鬆開 |
| 手機文字框尺寸與狀態不穩 | 用既有 16px 輸入、至少 44px 操作，長文字自然捲動而不可拖曳 | 390px 不水平溢位；錯誤、等待、焦點均不遮住下一步 |
| 查詢或日期錯誤缺乏清楚回復 | 篩選不改資料來源、範圍或分頁語義；提供欄位提示／重試 | URL 篩選保持原值；403、空資料、網路失敗仍分開呈現 |
| 今日工作切換卡片後搜尋消失 | 保留本機搜尋字串；卡片數字改用相同的授權名單、班別與搜尋口徑 | 切卡搜尋與筆數一致；只有明確按「查看全部」才清除搜尋、班別與待指派篩選 |
| 評估捷徑跳到單一量表，選案後合成資料與量表名單不同 | 新增獨立評估入口，先選已授權個案再選量表；展示名單與量表共用同一合成個案來源 | 未選案有欄位提示且聚焦；9 份題目式量表對合法合成個案可讀；無效個案仍拒絕；換案未確認時不顯示舊案連結；原 79 頁路由仍在 |
| 評估入口個案清單供應商讀取卡住 | 沿用既有伺服器讀取期限，超時顯示短錯誤及重新載入 | 讀取失敗／逾時不顯示空名單或別分支資料；重試不發寫入 |
| 手機收案步驟卡佔去大半首屏 | 五步驟保留可鍵盤操作，但 520px 以下改為單列橫向捲動、露出下一張卡；點步驟卡直接捲到工作表單 | 390px 無整頁橫溢、步驟可觸控與鍵盤移動；第一個基本資料欄位比原截圖 y=1271 更早可見，點卡後進入可見範圍 |

外部評估結果登錄尚缺保存未知／換案未保存保護，本輪不從新入口啟用；展示入口只提供使用相同合成個案 ID 的九張問卷。其他評估原入口不移除，但不把「可見」當成「已通過選案直達與正式寫入驗收」。

## 發布前驗收

1. 單元／元件與既有權限、個案生命週期、每日照顧回歸通過；ESLint、Typecheck、production build 通過。
2. 以實際瀏覽器檢查桌機、390px、鍵盤與中文組字：缺值、修正、成功、網路失敗、結果不明、返回；沒有原生驗證泡泡或重複寫入。
3. 驗證來源／授權拒絕不顯示成「沒有資料」；錯誤或逾時不產生已保存假象。個案分支與 Finance 外框不變。
4. UI 靜態稽核僅能證明本輪改動來源；不能代替正式 Google 登入、hosted API／RLS、真人個案資料、全 89 頁及 WCAG 人工驗收。
5. 部署只能在合適、已獲授權的商業託管方案與正式營運門檻內進行；不得以本機測試或 Git commit 冒充前台更新。
