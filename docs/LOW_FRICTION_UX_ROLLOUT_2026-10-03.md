# 日照系統低學習成本介面：分批實作與驗收

本文件是 UX 發布計畫，不是 89 頁正式營運、臨床規則或資安驗收證明。功能成熟度仍以程式、測試、權限與 `PRODUCTION_GATES.md` 的當次證據為準。

## 使用者看到的設計規則

1. 先呈現「現在要做什麼」：今日個案、未完成工作、下一個可用動作；工程狀態放入可展開的管理資訊。
2. 每一頁只有一個主要動作；次要動作、來源與說明按需展開。錯誤只解釋原因、資料是否已儲存、下一步怎麼做。
3. 選一次個案，後續入口帶入同一個案；頁首固定顯示目前個案與服務／評估日期，避免記錯人。
4. 用可讀的進度、狀態與圖示輔助文字，但不只靠顏色；待完成不得顯示為完成。手機先顯示工作內容，不讓導覽或說明佔滿首屏。
5. 上傳、儲存、切頁都有真實進度或結果；逾時不等於失敗，不能因重試產生重複個案或紀錄。
6. 視覺沿用 `DESIGN.md` 的 Finance 系列框架與色票；不得為了少一次點擊省略身分核對、逐欄 CMS 決策、權限、簽署或風險處置。

## 本批必過測試

- 在 390px、平板與桌機檢查首屏、文字、觸控目標、焦點、無橫向溢出；對照修改前後畫面。評估頁選人後應可立刻找到第一題，收案頁應立刻找到真正可用的建檔動作。
- 用鍵盤走完選個案、作答、返回未答題、修正答案、保存草稿與錯誤回復；頁面狀態不能只靠顏色。
- 在量表與收案各填入未儲存內容，測同頁換人、站內連結、瀏覽器上一頁／下一頁與重新整理：取消離開時內容保留，確認離開時一次到達目標；不得把答案或個資寫入瀏覽器 history state／Web Storage。
- 用合成個案驗證無權限、無 CMS 封存、載入失敗、重送、必填缺值；不放寬伺服器授權、資料來源或冪等檢查。
- 聚焦元件測試、全量 lint／型別／單元／資料庫編譯／build 通過後，再建立預覽版；預覽路由與手機實測通過後才合併正式分支並核對正式網域。
- 正式網域可用不代表真人收案、量表正式計分、CMS 封存掃毒、法遵或備份已通過。這些仍由 `PRODUCTION_GATES.md` 單獨把關。

## 發布後量測

請在實際授權帳號完成現場 UAT：各角色各找至少一名使用者，記錄「找到入口時間、完成任務時間、求助次數、誤選個案次數、保存重試次數」。每個未完成任務記錄頁面、設備、步驟與資料狀態。先修阻斷與誤判，再擴至下一批；不要以主觀漂亮程度取代工作完成率。

## 連續照顧與個案中心第二批（待本次發布驗證）

- 先修正照顧日誌按個案全量顯示造成的日期／班別混淆：只把台北服務日、所選班別完全相同的紀錄放在「本次」；歷史與其他班別保留在可展開區，不刪除也不靜默計為當班完成。
- 出勤簽到及生命徵象收到有效、持久化的回執後，才顯示下一步連結；連結保留穩定個案 ID、服務日與班別。離線待送、展示模式及回覆不完整時不顯示此連結。
- 新增日誌草稿以回執中的紀錄 ID 觸發同頁讀回；只有讀回相符版本後才提示可接續並聚焦，讀回失敗時提示保留原操作而非再新增。簽署仍是獨立、受權限與 AAL2 限制的操作。
- 個案中心保留所有伺服器 GET 篩選，讓搜尋及已套用條件常駐、進階條件收合；五張摘要卡在足夠寬的桌機同列，手機首筆個案上移。篩選結果、網址、返回與權限仍由既有契約決定。
- 照顧日誌的提交、簽署、退回及更正，在真正送出前顯示可取消的個案、項目、時間、版本與後果確認；不確定結果的重試沿用原請求與冪等鍵。頁面有個案名稱和代碼時用於現場核對，仍保留穩定識別碼。
- 切頁時由全畫面遮罩改為右上角精簡進度提示；原有切頁鎖定與載入狀態仍保留，不將 CSS 動畫當成實際效能改善。

### 下一批不得遺漏

- 交班需要獨立的發送、接收、確認與逾期狀態及伺服器契約；日誌備註不等於已交班。
- 目前高頻頁仍共用大型 catch-all 路由；既有本機 build 記錄首載約 669 KB gzip，須拆出熱路徑並以新 build 與網路量測驗證。個案中心目前先取授權全量再分頁，需在保留 RLS、總數與搜尋稽核前提下設計後端分頁。
- 日期與個案篩選的原生 GET 仍會整頁導覽。若改軟導覽，必須保留無 JavaScript fallback、草稿離頁保護、URL／返回及授權語義，不可只為動畫而改。

## 第三批：高頻入口首載分流

- 將「今日工作」和「個案中心」從涵蓋大部分員工頁的 catch-all 程式包拆為獨立路由，沿用原本的登入、頁面權限、個案範圍、篩選網址、錯誤狀態與 AppShell。這是降低首載成本，不是改寫照顧資料或授權規則。
- 個案資料頁明確設定為逐次請求動態繪製。即使建置環境暫缺 Supabase 設定，也不得預先產生或跨使用者快取內容；正式回應仍須有 `private, no-store`。
- 本機合成資料的冷載瀏覽器檢查：兩頁原本各請求 42 個 JavaScript 資源，拆分後「今日工作」23 個、「個案中心」22 個；均不再載入帳務、量表和人員管理的無關頁面程式碼。這是開發環境的請求數，不代表正式站延遲。
- 本機正式建置產物的「該路由引用之 JS chunk gzip 總量」基線約 532 KB；拆分後今日工作約 198 KB、個案中心約 186 KB。這個靜態指標不是完整網路轉輸量或互動時間，正式流量仍須以瀏覽器 RUM／50 人並行測試驗證。
- 本輪不改動個案中心的伺服器資料取得方式。它目前雖顯示 24 筆，仍先全取授權個案再在應用程式分頁；下一輪須以維持既有 RLS、姓名權限和同快照統計為前提，設計資料庫端分頁。今日工作之每週安排亦仍有資料載入瀑布，需實際延遲量測後優化。
- 發布門檻：兩路由在 build 中皆為動態；權限被拒時不呼叫資料載入器；已授權結果、日期與篩選、超界頁轉址一致；89 頁路由、390px 無溢出、鍵盤與正式站無快取標頭通過。未以展示資料或本機建置宣稱真人營運驗收完成。

## 第四批：減少資料瀑布與跨頁漏筆風險

- 首頁在頁面授權與服務日確認後，同時啟動照顧快照、分工名冊及「預計到站」讀取；後者仍在獨立 Suspense 區塊呈現，拒絕存取時三者均不啟動。這只移除順序等待，不新增跨使用者快取，也不改變原有錯誤、無資料與 55 秒更新語義。
- 生命徵象、照顧日誌及出勤頁在頁面授權與選擇檢查後，並行讀取當日快照和各自的即時操作權限。寫入 RPC 仍逐次驗證；讀取與寫入權限分開，資料不可用不能顯示為空白成功。
- 個案中心的指派資料仍依現有 RLS 讀取；1,000 筆一批的查詢增加唯一 ID 排序鍵，並在筆數不符、ID 重複或精確筆數缺失時停止顯示，避免將不完整結果當作正式名單。這不能解決跨請求變動造成的 offset 位移，也不是資料庫端分頁。
- 真正的資料庫端分頁須另做授權矩陣與差異測試：逐案可見範圍、指派與人名各自的 RLS；繁中搜尋及排序須與現行 TypeScript 完全相同；24／25／48／49 筆頁界、摘要／總數／責任人選項、零筆及權限撤銷須一致。不得以單一高權限函式聯結指派及姓名，或把 PGlite 結果視為正式 Supabase 證明；「同快照」也須解決現有寫稽核的 `VOLATILE` 函式可能取得不同 MVCC snapshot 的問題。
- 本批驗收：延遲受控測試證明獨立讀取同時啟動、無權者零讀取，跨批指派排序不漏重且錯誤閉鎖；全量程式、資料庫、路由及窄螢幕回歸；再以正式網域核對部署與私人不快取。沒有真人帳號與真實負載證據前，不宣稱 p95 達標或 Apple 等級的整體體感已驗收。

## 第五批：個案搜尋保留工作脈絡

- 本機合成資料改前量測：提交個案搜尋後 `window` 探針消失，證明原生 GET 導致整頁重新載入；結果仍正確，但側欄與頂列也重新初始化。
- 改用 Next.js 漸進式 GET 表單，保留原生無 JavaScript 提交與伺服器端權限重驗；關閉個案結果的路由預抓，避免為了體感提前載入敏感名單。篩選提交後保留 AppShell，焦點到結果標題；清除搜尋立即更新並回焦輸入框；瀏覽器返回／前進還原欄位與結果。
- 既有 24 人一頁與資料快照口徑不變。本批只移除整頁重載；資料庫端目前仍先取授權全量，下一批須依第四批安全設計完成專用分頁 RPC 與實際角色權限矩陣，不能直接查 `public.clients` 或從本機展示模式推論正式 p95。
- 本機改後瀏覽器驗證：合成資料搜尋、清除及返回／前進時 `window` 探針保留；390px、320px 無水平溢出，搜尋與清除觸控目標各至少 44px；篩選區 axe 未檢出違規。完整測試與正式部署結果另於本次交付記錄。

## 第七批：個案清單與附件等待狀態（已發布）

- 個案中心的有效指派查詢先由資料庫排除已結束區間，再做精確筆數與逐頁讀取；授權機構、分支、指派人及生效時間條件維持不變，讀回後仍做一次失效檢查。這減少大量歷史指派擠占查詢上限的風險，**不是**個案名單的資料庫端分頁，也沒有正式站 p95 證據。
- 登入關卡、MFA 與有效成員資格仍依序確認；成員資格確認後，所屬機構名稱與分支資料才並行讀取。任一讀取失敗仍不建立登入脈絡；不把登入速度優化變成越權預抓。
- 附件選檔後立即顯示名稱、大小與格式／大小錯誤；上傳中與讀回核對分別顯示狀態，只有掃毒回條和正式清單吻合才顯示完成。逾時或網路結果不明時保留選檔、欄位及原冪等鍵，暫停修改原檔與欄位，讓原次操作可安全重試；版本衝突須先讀回，若清單已有新版本，清除待送檔案以免變成另一次新版本上傳。掃毒尚未配置與展示模式仍禁止上傳。
