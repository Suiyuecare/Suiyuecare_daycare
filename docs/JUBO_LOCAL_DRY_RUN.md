# JUBO 本機資料對帳：唯讀 dry-run

`scripts/jubo_dry_run.py` 只讀取本機來源資料夾，將 JSON 報告寫到標準輸出。程式不連線 Supabase、不建立匯入批次、不寫資料庫、不上傳檔案，也不建立正式服務紀錄。它的用途是釐清來源欄位與缺漏，供資料負責人逐項確認；報告不是匯入核准或七年服務史證明。

```bash
python3 scripts/jubo_dry_run.py --source-dir /path/to/private/Jubo-export
python3 -m unittest discover -s scripts -p 'test_jubo_dry_run.py'
```

只接受一份主清冊格式 XLSX、一份在服務子清冊格式 XLSX；兩表以表頭精確辨認，不在程式中硬編人數。PDF 僅做檔案 SHA-256 清冊，不解析、不計算或匯入其中候選服務列。來源 JSON 側錄只統計視窗數與檔案參照數，沒有直接當作已取得完整資料的證明。來源 Markdown 只計雜湊，不讀取內容。未知檔案列為未解析。

## 對帳語意

| 主清冊 | 在服務清冊 | 僅供本機候選欄位 |
| --- | --- | --- |
| C 姓名 | H 姓名 | `displayName`，只檢查有值與同身分列是否完全一致；不能用姓名找人或合併 |
| Z 身分證字號 | AD 身分證字號 | `identityNumber`，只在記憶體內 trim、uppercase 並精確比對；報告不顯示原值、遮罩值或識別碼雜湊 |
| X 生日 | J 生日 | `dateOfBirth`，接受有效西元 `YYYY/MM/DD`／`YYYY-MM-DD` 或整數 Excel 日期序號 |
| D 性別 | I 性別 | `sex`，只辨認男／男性、女／女性、其他、未知 |
| AD 聯絡電話 | W 聯絡電話 | `phone`，只檢查有值與相同身分列是否完全一致 |

這是來源欄位位置與格式的唯讀候選映射，不是中央 CMS 欄位主權或正式入檔白名單。來源「編號」B 是獨立缺漏項，不以案號、姓名或其他欄位替代。來源狀態只計 active／suspended／closed；停用與結案需經正式生命週期覆核。首次服務日期只計有值與格式，不轉成 `admitted_on`、出勤或已執行服務。地址、CMS 等級、資格、核定照顧計畫、簽署及每日服務細節維持未映射。

同表身分值重複、跨表找不到唯一精確身分、欄位不一致、缺日期或來源編號，會成為人工覆核原因。每筆報告只顯示 workbook 角色、sheet 列號、由整檔雜湊與列號推得的定位碼，以及固定原因代碼；不輸出姓名、身分證、電話、生日、地址或原始來源檔名。雜湊用於確認來源檔案版本；它不是個案身分索引。

正式移轉前仍需來源穩定個案編號及字典、正式機構／分支範圍內可授權的目標快照、逐欄映射與缺值語意核准、完整原生服務匯出及七年覆蓋證據、原始檔封存／附件安全與正式交易及讀回驗證。既有 CMS 暫存回執不代表正式入檔。對帳報告本身含來源檔案雜湊與定位資訊，應留在授權的本機環境，不公開分享。
