# 題目式量表規則治理：候選版本

## 範圍與界線

本輪新增的是規則登錄、送審與獨立核准的資料庫／API 能力，不是臨床核准，也不是量表正式簽署完成。未對正式 Supabase 執行 migration，未代替任何人送審或核准。管理畫面的操作入口、正式評估簽署／更正及真人驗收仍須完成。

使用者已確認取得題目授權，並允許公開原始碼；本輪不以題目授權缺失作為阻擋理由。

## 不可變來源

- 九份候選量表包含完整題目、選項、權重、計分區間、來源、情境修正、獨立安全警示及測試向量。
- `canonicalRuleJson` 穩定排序物件欄位，保留題目／選項順序；SHA-256 對應完整 UTF-8 來源。資料庫同時驗證原文雜湊及原文與 JSON 一致。
- 候選登錄只新增部署擁有的題庫資料。公開 API、員工、匿名及 `service_role` 不可直接插入／修改題庫；不建立任何分支核准或個案簽署紀錄。
- BSRS 與 IADL 使用新的 v2 計分規則；題目／草稿版本維持 v1，與既有草稿資料庫契約相容。舊計分 v1 保留，不改寫歷史。
- BSRS 安全題的人工確認需求會獨立保存，即使其他題未完成也不消失。正式簽署還需實作逐項人工確認，不能將產生警示當成已處理。
- GDS 與 SPMSQ 的來源分級／教育歸組差異見 `ASSESSMENT_SOURCE_REVIEW_2026-09-26.md`，尚未替機構選定規則。MNA-SF 與跌倒 B12 子表不等於完整版 MNA 或 ABCD。

## 分支規則採用

1. 具該分支 `forms.manage` 的授權員工提出已登錄規則與生效期間。
2. 另一位具同分支權限的人員核准，使用不同人員及不同重新驗證證據。
3. 核准建立不可變採用紀錄；不修改題庫、角色模板或既有草稿。
4. 撤回只能由原申請人操作；退回由獨立審核人操作，皆須理由。
5. 不允許回溯生效、重疊生效或同一分支／量表多筆未決申請。

所有讀取與寫入都重新核對固定 Google 身分、帳號狀態、有效工作階段、機構、分支與當前角色。寫入要求近 15 分鐘實際 AAL2 因子及伺服器證據；這不是把一般草稿作業重新改為驗證器登入。高風險驗證政策仍待產品負責人確認，未在本輪放寬。

交易使用同一分支／量表鎖及人員／冪等鍵鎖，等待後與完成前再核對授權。API 嚴格核對回執的機構、分支、作者、冪等鍵、表單、來源雜湊、動作、申請、決議與時間；無法完整核對時回傳「結果尚未確認」，不回傳原始資料庫錯誤。

## 審核 API

`GET /api/questionnaire-rule-reviews?form_key=...`

- 固定當前登入者的機構／分支，不接受用戶指定其他資料範圍。
- 每頁最多 20 件申請、50 份題庫摘要；游標時間與 ID 必須成對提供。
- 回傳當前程式候選及其是否已登錄；登錄不等於啟用。
- 審核歷程不包含個案答案或個案個資。

`POST /api/questionnaire-rule-reviews`

- 必須提供 UUID `Idempotency-Key`，所有 UUID 正規化為小寫。
- 僅接受 `action`、`formKey`、`catalogHash`、`requestId`、`effectiveFrom`、`effectiveTo`、`reason` 七個欄位。
- 動作限 `request`／`approve`／`withdraw`／`return`。題目、計分結果、審核人或資料範圍不可由用戶注入。
- 日期及登錄狀態的權威檢查發生於資料庫冪等查詢之後：已提交請求即使跨日或程式升版，仍可用原內容與原鍵取得歷史回執。
- 日期、來源及內容不同時不得重用相同操作鍵；原始內容不明時不得自動產生新鍵重送。
- 在身份／近期驗證通過後、讀取內容前，核對設定的系統來源、瀏覽器 Origin、Fetch Metadata 及完整 JSON MIME。不能以 Host 或代理標頭推導信任來源；來源或格式不符時不讀取內容、不呼叫業務 RPC。這是加強防護，不表示已證實原版存在瀏覽器跨站漏洞。

## 規則退休

- 獨立、不可變的退休申請／核准 RPC 與採用流程使用相同分支／量表鎖；不得修改原採用日期、題庫或既有答案。
- 退休需另一位授權人員以不同近期驗證證據核准。等待期間停權會使操作失敗，事件、回執與讀取稽核均不留下部分寫入。
- 實際有效截止日取原期限與已核准退休期限中較早者。未來正式簽署須在同一鎖內取得這個截止日，不得只讀原採用列的日期。
- 退休 TypeScript 契約與 143 項單元測試已完成，忠實接受 SQL 的七鍵輸入（核准的 effectiveThrough 為 null），嚴格綁定機構、分支、activation、題庫、操作與決策回執。區分原始期限及衍生截止日，拒絕不可能的完整歷程與超過微秒精度的時間；缺少完整歷程時不推定尚未退休。
- 退休 HTTP 已完成本機候選，但管理畫面、真人完整操作與 hosted 驗收尚未完成；資料庫／API 能力不能當成現場可操作的完整功能。

## 退休 API

`GET /api/questionnaire-rule-retirements?activation_id=...` 固定登入者機構／分支，使用真正 SQL 參數 p_activation。游標必須成對、UUID 正規化、小數最多六位，不接受重複或未知篩選欄位；例行讀取不要求第二因子。

`POST /api/questionnaire-rule-retirements` 依序驗證登入／forms.manage、近期實際 AAL2、設定來源／JSON 格式、操作鍵及最多 8,192 bytes 的七鍵內容，再呼叫唯一寫入 RPC。核准不能重寫原申請期限；相同鍵重播不另查今日日期、現行題庫或待審歷程。結果不明保留內容及原鍵，不自動改鍵重送。

97 項 API 測試通過，包含拒絕前不讀內容／不呼叫 RPC、跨範圍或不相關回執、精確重送、分頁與安全錯誤。這些使用合成 SDK 回覆，不是 hosted HTTP／真人驗收。

## 驗收與未完成項目

已完成的本機檢查：

- 題庫 20 項測試，包括逐一核對九份來源與 migration 內的完整原文／雜湊。
- 審核 API／回執契約 169 項測試，包括跨機構反向、第二人證據、未知欄位、錯誤不洩密、精確冪等、微秒排序、跨時區時間與內容讀取前的來源拒絕。額外拒絕超過 PostgreSQL 六位小數精度的游標，保留合法六位游標，避免 SQL 四捨五入造成誤判載入失敗。
- 同來源 JSON 防護 63 項測試；題庫、契約、API 與防護共 252 項聚焦測試通過。
- 實際 PostgreSQL 17.11 編譯 136 份 migration，規則採用／退休 137 項 pgTAP 斷言通過；另以不同資料庫 PID 驗證等待中的權限撤銷、退休與新版本競爭、原始完整回執重播。未替換授權函式，也未連線 hosted 資料庫。
- 原生測試僅在確認自行建立的暫存 cluster 已停止後，刪除該次 data 子目錄；紀錄、備份與 evidence 留存。失敗或無法確認停止時保留資料，不掃描／清除其他舊測試目錄。
- 追加原生重現修正退休讀取與正常核准跨快照：新增 migration，不改歷史；137 migrations、141 pgTAP 與六個實際鎖等待探針通過。讀取及寫入共用 scope 鎖，等待後授權失效會拒絕；核准前後的歷程與截止日各自完整一致。

尚待完成：

- 規則核准後的正式評估簽署、更正版、完整內容雜湊及安全警示人工處置證據。
- 機構業務人員的規則選定與雙人實際核准，不由工程測試代替。
- 精準 hosted migration、正式角色矩陣及真人完整作業驗收。
