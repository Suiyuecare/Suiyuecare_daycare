# 臺北市 115 年 ABCD 附件：日照逐欄對照與正式驗收缺口

狀態：來源核對完成、候選草稿對照；**非正式表單發布、非本人簽署、非已通過主管機關驗收**。本文件只盤點使用者提供的官方附件與程式現狀，不含真實個案答案。

## 唯讀來源與範圍

- 來源：使用者提供《附件一、115年度臺北市政府社會局社區式【品質抽監測ABCD表】》，15 頁、A4、PDF SHA-256 `64bb716b19362580295fe8ee2e452d32e82d6f3c67773d5956f66c7e17d3c481`。A 表第 1 頁標示「114.11 修訂」，與適用年度 115 分開記錄。未把原 PDF 加入 Git 或部署。
- 第 1–2 頁 A：日間照顧個案基本資料；第 3–12 頁 B：需求初／複評、問題清單、個別化照顧計畫；第 13–14 頁 C：每月照顧計畫執行紀錄。
- 第 15 頁 D 的原題名是「臺北市小規模多機能服務臨時住宿紀錄表」，D1–D9 是住宿期間資料。本產品目前限純日照，**D 不適用，也不得把 CMS 服務代碼 D 或住宿紀錄變成日照必填**；若未來取得小規模多機能服務資格，需另立產品／法遵範圍與版本，不能沿用本候選草稿。
- 每一個輸入鍵、型別、選項、上下界、原稿頁碼的機器可讀對照，位於 [`src/lib/taipei-abcd/catalog.ts`](../src/lib/taipei-abcd/catalog.ts) 的 `TAIPEI_A_SECTIONS`／`TAIPEI_B_SECTIONS`／`TAIPEI_C_SECTIONS`。同一白名單凍結於 `private.taipei_abcd_field_spec()`；測試逐鍵核對兩者完全一致。以下矩陣按原表區段列出完整鍵群與尚欠證據，不以籠統「有頁面」代替逐欄驗收。

## 放行順序與驗收

1. **候選輸入一致性**：A 80／B 431／C 3 個鍵，型別、選項、上下界與資料庫白名單全等；每鍵可由 `sourcePages` 回到原 PDF；D 被前端解析及資料庫拒絕。現有 pgTAP／Vitest 加本次頁碼回歸可證候選欄位，不證正式合規。
2. **官方內容及責任人覆核**：主管／護理／社工逐欄核對原 PDF、條件必填、互斥／不適用、SPPB 與分數公式；對 A20 多選、B13／B14 版次等有歧義者記錄決議。未解決重大差異為 0。
3. **證據串接**：A22 與 B9 真附件完成掃毒、存取管制；C1 每時點量測與原值核對；B 計畫項次對 C2 執行逐筆連結；C3 有活動／互動來源。欠缺來源時必須顯示未完成，不可補造。
4. **本人簽署與輸出**：依 A/B/C 原稿的各角色完成本人簽署、近期高強度重驗、內容雜湊及更正版；官方版面／欄位、頁數、字型、空值、列印與 PDF 比對一致。行政核准仍不等於本人簽署。
5. **實機驗收**：用正式 Google 員工帳號與分支內個案測試新增、儲存重送、衝突、送審、退回、更正、簽署、匯出及手機操作；跨分支與撤權拒絕、稽核無明文個資；才可將 `pending_approval` 版本另行發布。此次文件與候選回歸**不構成上述放行**。
