# 中央 HTML 正式入檔門檻（工程／管理用）

狀態：2026-09-10 本機程式盤點與待辦基線。本次僅改善第 80 頁說明與核對介面，**沒有實作正式入檔、正式儲存介面或雲端設定**，也未讀取或驗收三份真實個案 HTML。

## 三個階段不可混稱

1. **已解析**：靜態解析器取得來源區段、欄位、警示與候選路徑；不是正式業務欄位映射核准。
2. **待核對／暫存核准**：人員核對來源及衝突；資料庫既有 `approve_import_staging` 只更新暫存核准資訊，回執為 `staging_only: true`。此回執不是正式入檔成功證據。
3. **正式入檔尚未完成**：須有守門交易將核准快照寫入明列的業務資料表、逐欄來源、版本及收據。本階段目前未接線。展示記憶體儲存器的 `imported` 狀態亦不構成業務資料表寫入證據。

## 下一個安全最小垂直切片（待實作）

第一個正式入檔切片只處理**經核准白名單的中央個案基本欄位**，先以合成資料在隔離測試環境完成以下閉環：

1. 固定版本、明列欄位映射與主權規則；保存原值、正規化值、來源定位及警示。未識別欄位不丟棄，不默認可寫。姓名只能顯示，不能作自動合併鍵。
2. 以穩定識別碼精確找到單一、同機構／分支的個案；無匹配或多匹配均阻擋。測試介面亦不可僅信任呼叫者傳入的個案 ID。
3. 產生不可變入檔提案：列出舊值、新值、來源、主權規則、映射版本及基準資料版本；授權人逐欄決定衝突。未提供值與明確清空／不適用分開，不默認覆寫。
4. 原始檔先取得固定物件版本、SHA-256、KMS 與七年 Compliance 保留證據；附件另外清冊化、隔離與掃毒，不自動抓外部網址。
5. 單一受控資料庫交易重新驗證登入、資料範圍、近期 AAL2、提案版本、映射核准、來源封存與衝突決定，再一次寫入白名單基本資料、逐欄來源、版本與不可變回執。冪等鍵需綁定操作內容及身分／範圍；相同鍵不同內容拒絕。
6. UI 只有取得正式回執，且正式個案查詢可讀回同一版本時，才能顯示「正式入檔完成」。歷史暫存回執不得推導為完成。

**不納入首個切片**：核定照顧計畫、額度、費率、資格核定、醫囑、用藥、量表分數、每日執行／服務紀錄、申報及簽署。官方核定／簽核日期只保存在來源證據，不能偽裝成本系統當次簽署。既有已簽紀錄、臨床角色與雙人覆核限制維持不變。

## 失敗、重試及保存邊界

- S3 與 PostgreSQL 不是同一交易，不能宣稱跨服務全域原子性。先封存再進正式資料庫交易；交易失敗時業務資料變更必須為 0，但已建立的 WORM 物件可能保留。
- 對保留物件建立孤兒清冊、原因及後續對帳；不得刪除或縮短 Compliance 保留期限來「回滾」。重試沿用原始建立時間及物件版本，不重新推算造成保留／回執不一致。
- 解析、重新解析、暫存核准、正式入檔各自具有不同回執。逾時視為結果未知，不以 UI 成功通知推定寫入；可用相同冪等鍵查驗或安全重試。
- 預覽不可只靠欄位名稱正則遮罩保護個資；正式版須核定逐欄資料分類與顯示權限，未知欄位應保守限制。不得將原始欄位、附件、Token 或金鑰寫入一般記錄檔。

## 需要資料負責人確認的事實

既有計畫已確立「中央身分／資格／官方核定資料優先，本系統執行紀錄優先」；不需要重問此原則。但下列缺失事實不能由工程猜測：

- 三份來源欄位字典、確切穩定識別碼、例外資料、每個目標欄位與責任人，以及缺值／清空語意。
- 哪些白名單基本欄位可正式覆寫、哪些衝突一律保留人工佇列，與映射版本核准紀錄。
- 原始檔與附件保存、資料區域、供應商及資料退出審查的完成證據；物件保存規則不等同全部法遵驗收。
- 未來核定計畫／申報切片的現行官方格式、年度／縣市／生效日及法律／業務審查；本切片不自行創設公式或規則。

## 本機驗收清單（未全數實作）

- 合成正向流程：預覽 → 明確核對 → 正式交易 → 讀回同一個案版本與逐欄來源，回執清楚區別暫存和正式。
- 跨機構、跨分支、錯個案、失效身分、過期 AAL2、缺角色、變更後基準版本、未核准映射全部拒絕。
- 未知欄位、同批衝突、既有值衝突、欠缺附件安全或封存證據不得靜默通過。
- 冪等重送不重複寫；同鍵不同內容拒絕；並行核准只允許符合基準版本的交易。
- 逐步故障注入（基本資料、來源、版本、回執）確保整個正式交易回滾、業務資料變更為 0，WORM 孤兒可對帳。
- 更正只能新版本；不能借中央匯入修改本地已簽紀錄、繞過雙人覆核或把中央簽核偽裝成本機簽署。
- 未登入、直接 API、跨範圍及欄位權限矩陣均測試；日誌不含明文個資／附件／憑證。
- 三份黃金樣本、正式雲端封存、資料移轉彩排及正式環境驗收另行取得證據；合成測試通過不能替代。
