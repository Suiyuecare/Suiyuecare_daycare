# JUBO 待收案主任草稿：隔離候選版

此版**尚未合併、未部署、未開通任何真人帳號**。它依賴尚待安全審核的 `20261009102100`／`20261009102101` 待收案主檔候選 migration；不能單獨發布。沒有 JUBO `public pending link` 的個案完全不能使用。

## 權限邊界

- 只接受公司已逐人核准、尚有效的 Google 員工工作階段，以及該分支明確指派的系統 `branch_director` 角色。新權限 `clients.intake_draft.manage` 只授予此角色模板；不增加 `clients.manage`、護理、社工、出勤、排車、用藥或申報權限，也不開通任何使用者。
- 僅限 `status=pending`、`source_system=jubo`、尚無正式收案日、已有來源核對連結的個案。跨機構、跨分支、未核准 Google、撤權與沒有來源連結均拒絕。
- `public.save_jubo_pending_director_draft` 接受冪等鍵與預期修訂版。`local_supplement/intake_local` 只能保存聯絡偏好、到站規劃備註及待追蹤備註；中央身分、資格、同意與原始欄位不能改。
- `assessment_preparation` 可按指定量表鍵保存表單版本標籤、評估日期、答案與質性備註，但只是**未驗證、無分數的準備草稿**。它不建立正式量表結果，不得被列入臨床判斷、申報或對外匯出。正式量表題目、計分、簽署仍須走各自的核准流程。
- 草稿存在私有、強制 RLS、不可修改的修訂表；來源連結與來源列 ID 留在每一版中。`public.jubo_pending_director_draft_workspace` 只回傳該待收案個案最新草稿。讀寫有稽核，稽核不含草稿內容。

## 放行前仍需完成

1. 修正上游待收案主檔候選版：完整 `IntakeProfile`、來源版本和逐欄主權，並覆蓋全部正式作業後端阻擋；目前 23 筆個案尚未轉正。
2. 在正式 PostgreSQL／Supabase 環境跑角色、RLS、並行寫入和同分支真人操作驗證；PGlite 只證明本機 SQL 相容與合成權限矩陣。
3. 表單前端依正式題庫版本串接此準備草稿，明確標示「非正式紀錄」，並在收案後提供人工覆核移轉流程；不得自動升級為已簽署量表。
4. 完成東京環境資料庫、原始來源封存、23／17 筆逐筆核對與主管核准後，才可考慮發布。
