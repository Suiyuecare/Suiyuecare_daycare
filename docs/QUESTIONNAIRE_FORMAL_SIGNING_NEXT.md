# 正式量表簽署：下一輪實作邊界

本文件是增量設計，不代表已實作、臨床核准或正式部署。先涵蓋目前九份題目式量表；其他評估頁與完整 MNA 不得因此標示完成。

## 保留既有資料

- 題目式草稿版本仍只允許 draft；新增、修訂、歷程與既有 RPC 契約不變。
- 正式簽署另建私有、強制 RLS、不可改寫／刪除的版本及操作回執。
- 同一來源草稿只能簽一次；更正必須連到原紀錄與前一正式 head，保存理由，不得分叉。
- 正式最新版本不會被後續草稿取代；新草稿須顯示待核簽。

## 授權與待決政策

- 一般 Google 草稿作業不變；正式簽署的最終額外驗證方式已另向產品負責人確認，未自行放寬。
- 不直接重用要求 forms.manage 的治理重新驗證函式。臨床簽署需自己的機構／分支／個案／表單／簽署權限與資格驗證。
- 照服員現有 ADL／IADL／跌倒草稿權限不等於核簽權限；主任兼任護理／社工須另有有效授權，不推定臨床資格。
- staff_certificate_versions 可保存資格證據，但 certificate_type 是自由字串，必須由機構正式核准逐表資格規則，不猜證照名稱。
- 尚待真人確認：逐表核簽角色、風險確認人與追蹤期限、補登、評估日跨規則期間及更正處理政策。

## 不可變簽署交易

1. 固定順序鎖住人員／操作鍵、治理分支／量表、草稿 assessment 鏈。
2. 讀取已保存的明確草稿版本及內容雜湊，不接受瀏覽器分數或簽署人／時間。
3. 初簽使用唯一已核准規則，且期限取 private.questionnaire_rule_effective_through，包含退休結果；更正固定原正式規則，不以新規則重算歷史。
4. 從不可變題庫重算完整答案、分數、分級與獨立警示；不執行 JavaScript／SQL 公式文字。
5. 安全警示確認須綁定來源草稿 ID／雜湊、catalog 雜湊與警示 fingerprint，保存真人、資格、時間及後續處置。草稿／規則變更使舊確認失效。
6. 保存答案、規則及來源快照、完整內容雜湊、簽署目的、角色／資格／驗證證據、伺服器時間與固定回執。
7. 等待後及寫入／稽核完成前再次驗證授權、資格與驗證效期；任何失效使整筆交易回滾，新增版本／回執／稽核為 0。

相同操作鍵與內容重播原始收據，不能改內容後自動換鍵重送。停用後的讀取／重播仍須拒絕；不同鍵簽同來源或更正過期 head 回衝突，不重簽或分叉。

## 必要驗收

### 規則封存還需涵蓋的驗證（2026-09-26 計分完整性審核）

目前九份 candidate 的可達完整答案總分、情境分類及 BSRS 獨立安全警示都有可重現測試，但不能把 `scoreTable` 當成完整簽署驗證器：

- 通用缺答、不適用與無效選項的結果／錯誤契約尚未完整結構化封存。正式交易須拒絕缺答及無效答案，不能把缺值算成零；亦須重現必要的不適用與情境政策。
- MNA-SF 的實測值、單位、小數精度、合理範圍、BMI 公式、BMI／小腿圍互斥及答案與測值一致性仍由 `preview.ts` 及既有草稿 SQL 驗證，未完整進入候選 manifest。純總分計算可完成而草稿預覽仍判未完成；不能直接拿純計分完成狀態允許正式簽署。
- `sourceSnapshot` 現有 URL／名稱不是來源原檔的 SHA-256、取得日期或封存證據。正式來源驗收須另保留原件與審查證據，不能以連結存在替代。

後續須新增版本化的結構驗證契約並建立新 hash／審核，不得改寫已凍結的九份候選 hash、已採用期間、歷史答案或分數。GDS 分級來源、SPMSQ 修正政策與逐表資格仍依前述真人決策處理；本輪不自行決定臨床政策。

2026-09-27 已新增獨立的結構驗證候選及固定雜湊，並由封存的錯誤規則與原計分表進行候選重現；見[結構驗證候選範圍與證據](QUESTIONNAIRE_VALIDATION_CANDIDATE_2026-09-26.md)。它只描述既有資料庫草稿 wire，不取代 HTTP 前處理、授權、來源證據或正式簽署。新的私有組合目錄／雙人採用與正式交易仍未接線；原九份 v1 不變，不能據此回溯認定舊採用已包含新驗證器。

`rule-catalog-completeness.test.ts` 的 36 項新增測試包含上述邊界，以及特殊無效版本名稱的安全拒絕回歸；這些是本機測試，不是 hosted 或真人簽署證據。

- Node 與資料庫對九份完整固定答案、全部界線、情境與安全警示結果完全一致。
- 跨機構／分支／未指派、角色但無資格、無有效簽署權限與驗證證據均拒絕。
- 改 source ID／hash、偽造分數／簽署人／時間、NULL／未知欄位／缺答與舊警示確認均拒絕。
- 真正多 backend 驗證簽署與草稿修訂、退休、資格／指派／工作階段撤銷，以及兩人更正同 head 的競爭。
- 新規則、退休、更正與精確重播不改變原始正式內容、分數、來源、簽署人及時間。
- API 回執嚴格綁定機構／分支／個案／表單／操作與版本；未知結果保留原內容及鍵重試。
- 真人以手機 390px、鍵盤與螢幕閱讀器完成選個案→作答→預覽→風險確認→簽署→更正；不能只驗 API。

上述政策、後端與前台全部通過後，才可由雙人真人核准規則並開始正式量表營運。
