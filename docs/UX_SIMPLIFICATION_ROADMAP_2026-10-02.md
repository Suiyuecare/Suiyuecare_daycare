# 日照系統低學習成本改造與發布驗收

目標不是隱藏照顧責任，而是讓現場人員每次只看到當下可做的工作。保留 89 個既有入口、正式欄位、簽署、權限與稽核；縮短入口、降低重複輸入、將工程說明移至治理頁。Finance 的側欄、頂欄、字級與色彩以現有設計規範作為外框基線，不能用視覺相似取代實際登入與資料驗收。

## 導覽與畫面規則

1. 登入後先到「今日工作」；依職務顯示已授權的今日個案、下一件事與待處理數，卡片只放個案、狀態、主要動作。完整明細與來源以可展開區塊呈現，不刪除必要資訊。
2. 個案、日期、班別由同一工作脈絡接續到出勤、量測、日誌；變更個案須清除前案班別，無排班或多班不得猜測。日期級出勤不可標成班別已完成。
3. 題目式評估先選個案、日期、評估人，再直接顯示題目；一題一區塊，選項可點、提示可讀、儲存動作唯一且清楚。手機短視窗不得讓固定導覽或軟鍵盤蓋住題目與送出結果。
4. 空資料、無權限、載入失敗、離線與結果不明各用不同短訊息和下一步，不能把失敗顯示為 0，也不能重送可能已保存的臨床紀錄。
5. 工程字詞與長篇解說移至治理／說明區；現場仍保留藥物、風險、簽署、來源與更正的必要告知，不把高風險資訊藏到無法察覺。

## 分批落地

| 批次 | 範圍 | 可驗收的完成條件 |
|---|---|---|
| A：連續工作 | 今日工作、個案接續、出勤／量測／日誌、手機量表儲存 | 單一已確認班別接續；多班須選、換案清班；實際時間與日誌班別一致；390×560 首屏看得到第一位個案及主要動作，篩選仍可展開；手機不橫溢、儲存與錯誤可見；原筆重試與權限不變。 |
| B：表單簡化 | 9 份題目式量表、A／B／C、收案與附件 | 選案後首屏可開始填寫；每題有完整可及名稱／提示；保存、草稿、正式簽署與來源狀態分開；錯誤回到欄位且不清已填資料。 |
| C：角色工作台 | 照服、護理、社工、主任、財務、老闆 | 同一資料來源產生各職務可執行待辦；數字可下鑽、跨分支與敏感欄位不可越權；不把未授權或載入失敗當空清單。 |
| D：全站一致性 | 89 頁視覺與互動盤點 | Finance 外框、元件尺寸、標題層級、按鈕／空狀態與行動版一致；逐頁無空殼、不可用按鈕或無法載入。 |

目前 A 已有本機候選，B 正分段實作；不宣稱 B–D 已完成。B–D 需逐頁對照既有功能矩陣及臨床／主管機關表單版本，不能因畫面精簡而自行改動題目、計分、醫囑或法定欄位。

## 每批共同驗收

- 以照服員、護理、社工、主任、管理員各自的實際授權登入；檢查跨個案／分支／角色拒絕，直接 API 呼叫也不能繞過。
- 桌機、平板、390×844 與 390×560 真瀏覽器驗收；鍵盤、螢幕閱讀器及 200% 縮放另行人工檢查。觸控目標至少 44px，手機輸入文字至少 16px。
- 任務從已選個案開始，目標三次主要操作內完成高頻紀錄；用至少 10 位首次使用者觀察錯誤率、完成時間與需協助次數，與改造前基線比較。未做使用者測試不得稱學習成本已下降。
- 保存回條、清單讀回、已簽版本與 PDF／匯出分別核對；結果不明維持原操作鍵與內容，不能以重新整理假裝提交成功。
- 本地 lint、typecheck、單元／資料庫、build 與瀏覽器檢查只是候選；正式發布仍須依 `PRODUCTION_GATES.md` 完成雲端 migration、真人 Google 登入、RLS、封存／掃毒、備份還原與並行測試。發布後再查自訂網域的部署版本及關鍵讀寫流程。
