# 逐項改善：第一批匯入防錯與真實狀態

日期：2026-09-11。狀態：本機實作與驗證；未推送、未部署、未啟用雲端寫入。

## 本輪範圍與順序

沿用使用者確認的順序：中央 HTML 正式入檔 → 今日排程與照顧完成流程 → 實際服務申報與對帳。本輪先完成第一項前置的安全比較／回執／封存檢查，以及會誤導現場人員的共用頁占位統計；不把前置完成宣稱成正式匯入完成。

## 已實作

1. **共用頁真實狀態**：正式模式不再顯示固定 1／2／3、假更新時間或將未接線說成 0 筆。未開放時引導使用現行紀錄流程；合成展示明示資料性質，管理資訊預設收合。詳 `SHARED_WORKSPACE_TRUTHFUL_STATES_ACCEPTANCE.md`。
2. **重送完整性**：展示匯入操作綁定機構、分支、人員、操作類型與內容。保存每次操作的原始回執，拒絕跨操作或變更內容重用鍵；暫存核准後不可重新寫入。這是記憶體參考實作，不是跨伺服器持久化保證。
3. **暫存核准回執**：`POST /api/imports/{id}/approve` 改回 `{ batch, staging_only: true, formally_imported: false }`，批次維持 `ready_for_approval` 並有不可變核對資訊。不再將展示暫存標示 `imported`。此回應契約變更必須與後續用戶端一起發布；目前匯入頁沒有正式核准按鈕。
4. **差異提案引擎**：`promotion-preflight.ts` 為 server-only 純函式，只允許現有姓名／出生日期兩個基本欄位作候選比較，不內建或猜測中央官方欄位映射。以明列的穩定識別、同機構／分支及基準版本比對，不依姓名合併；保存舊值、新值、來源、主權與未映射內容。必填清空、歧義、過期版本、不合法日期均阻擋。輸出含個資，不得記錄或直接傳到瀏覽器。
5. **原始檔封存核驗**：PUT 成功後以固定版本 HEAD 確認 KMS、COMPLIANCE、保留期限、批次、初始時間、大小及可取得的 checksum。讀取前重驗 scope／版本，讀回後再驗 bytes。錯誤只顯示固定訊息，不包含 SDK 原文。API 改為 `archive(scope, batchId, bytes, sha256, createdAt)` 與 `read(scope, batchId, reference)`；舊缺少初始時間的參照不再可直接使用。

純提案固定為 `draft_dry_run`、`executable: false`，即使有核准參照字串也不能當成授權；未連接資料庫、API 或正式寫入。WORM 適配器沒有註冊啟用，沒有建立付費資源或新的七年不可刪物件。

重送覆核另修正：已是重複檔案的上傳也登記本次人員／鍵／檔名／雜湊，重送保留原回執；`duplicate` 與 `replayed` 可同時為 true。相同內容改名須由瀏覽器實際檔案 SHA-256 核對，不能只比檔名或大小。前端禁止處理中換檔及重複發送；雜湊不符時不取得預覽，保留原鍵供安全重試。已核准後只可取得先前成功重新解析的同操作回執，不能以新鍵重新解析或變更資料。

## 原始樣本核對

- 只讀取使用者已提供的三份本機 HTML；原檔保持原樣，沒有複製到 git、公開網站或附件服務。
- 以正確樣本順序確認 42／41／40 個區段。最初順序反向造成兩項 count-only 斷言失敗，核對後調整執行順序，沒有修改預期總數或解析器來迎合測試。
- 測試攔截 `fetch`、HTTP／HTTPS request/get，禁止外部請求，五種 API 呼叫次數均為 0；不以瀏覽器開啟 HTML。
- 斷言失敗只輸出數量，避免測試框架序列化來源內容。沒有將個資、欄位值或原始 HTML 寫入測試紀錄。
- 此次僅證明靜態解析區段與網路邊界；不代表逐欄語意正確、映射已核准、附件已掃毒或正式入檔成功。

- 共用頁：17 項元件測試；實際合成展示路由及空合成資料的正式模式元件 fixture 完成 1440／390 前後比較，沒有整頁溢位，主要操作至少 44px。
- 差異提案：23 項合成測試。
- WORM：57 項 S3 模擬測試；不代表真實 AWS 驗收。依 [AWS HeadObject 規格](https://docs.aws.amazon.com/AmazonS3/latest/API/API_HeadObject.html)核對固定版本與 checksum 行為；正式 IAM／KMS 權限仍待驗收。
- API 路由：上傳 → 遮罩預覽 → 暫存核准 → 同鍵重送 → 拒絕核准後重新解析；跨分支與無權限、舊驗證、未配置儲存、例外訊息遮蔽均測試。使用真正 route handler／service／記憶體實作，但登入 context 為合成 stub，不是正式 Google 工作階段驗收。
- 資料庫相容性：原有 97 migrations 編譯、暫存核准及執行長登入兩套 121 斷言通過；其中一套為既有 PGlite-only 多角色 fixture，另一套強制執行長限制。沒有修改 migration 或雲端資料庫。
- 全案最終回歸：`pnpm lint`、`pnpm typecheck`、`pnpm build`、`git diff --check` 通過；Vitest **316 檔／3,286 測試通過**，三份原檔的選擇性唯讀測試另外再跑 **3／3 通過**。建置仍有既存 `preferredRegion` 棄用警告，本批未更動部署區域。
- React 檢查：未新增個資本機快取；個案提案保持 server-only；檔案 hash 與上傳具必要相依順序，in-flight ref 防止重複事件，前端測試使用真實 WebCrypto 與 FileReader，而非固定雜湊假服務。
- 最後以 390px 瀏覽器串真正本機展示 handler：首次上傳 201 → 同 bytes 改名上傳 200 duplicate，批次與實際 SHA-256 相同；pending 禁止換檔／重複送出，合計 2 次 POST、外部請求 0、pageerror 0、scrollWidth 390。截圖 `/tmp/daycare-shared-metrics.HHYt0t/import-renamed-duplicate-390.png`，重現腳本同目錄 `verify-import-duplicate.mjs`。首次「所有 alert 均為 0」檢查過廣，改為檢查上傳錯誤，保留應存在的「尚不能正式入檔」警示；不隱藏業務限制。展示伺服器與瀏覽器工作階段均已關閉。
