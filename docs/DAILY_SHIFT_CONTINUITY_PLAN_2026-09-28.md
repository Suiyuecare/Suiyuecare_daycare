# 每日照顧：班別接續與明確選擇

現場目標：照服員從「今日工作」進入出勤、量測、日誌時，個案與日期不變，已確認的單一班別也不中斷；不讓日期層級的出勤誤變成班別層級紀錄。

| 情境 | 操作規則 | 驗收 |
|---|---|---|
| 僅排上午或下午 | 出勤仍以個案／日期登錄；連結額外攜帶已確認班別作為下一步工作脈絡 | 出勤畫面不稱「上午出勤」，進量測／日誌後保留同一班；日誌選項與來源班別一致 |
| 同日排兩班 | 未選班時出勤連結只帶日期／個案，不猜班別；選了清單班別才帶到下一步 | 兩班未選時日誌不預設全日；明選上午／下午後三步連結保留選擇 |
| 無排班或直接開頁 | 不把缺班別解讀為全日 | 新日誌先顯示「請選擇班別」，未選不能送出；使用者可明確選全日 |
| 更換個案 | 清除前一位個案的班別，不把 A 的上午或下午沿用給 B | 「更換個案」及再次選定 B 的連結都不含前一位的 `shift`；B 的日誌須重新選班 |
| 補登或跨班時段 | 發生時間是實際照顧時間，不以填寫當下代替；上午與下午以臺北時間 12:00 分界 | 過去服務日不預填時間；表單、API 與本地資料庫拒絕班別／發生時間相反，欄位聚焦並保留內容 |
| 草稿、切頁與異常 | 沿用既有未保存確認、原操作鍵與權限檢查 | 取消不失輸入；未知結果只能以原筆重試；無權限連結不出現 |

來源與界線：班別只依當頁已確認分工或使用者明選，不是授權依據；網址中的班別也不表示已核對新個案的排班。真正寫入仍由伺服器重新驗證。日誌表單不得改寫已簽紀錄，離線草稿不當作伺服器保存。本切片不改出勤判定、臨床規則、MFA、Finance 外框或正式部署門檻。資料庫新增的 `NOT VALID` 約束只保護新寫入與修訂，不回寫歷史；缺結構化班別的舊日誌仍可能由舊排班查詢按發生時間計入班別，須另列資料清查。

發布門檻：元件／流程回歸、完整 lint／typecheck／build、桌機與 390px 真瀏覽器同合成案例。這些本機證據不等於正式環境登入、RLS、保存或安全封存驗收；正式上線仍受 `PRODUCTION_GATES.md` 約束。

正式 migration 前，授權資料管理員須在目標資料庫唯讀執行下列彙總查詢，不匯出個案明細。若結果不為 0，先逐筆核對原始時間、班別及簽署狀態，訂出合法更正流程；不得以直接更新已簽資料方式清掉差異。新約束雖不掃描舊列，舊列日後修訂仍會受檢查。

```sql
select count(*) as local_diary_shift_time_mismatches
from public.care_records
where category = 'staff/daily-care/care-diary'
  and source_system = 'local'
  and (
    (data #>> '{fields,shift}' = 'morning'
      and (occurred_at at time zone 'Asia/Taipei')::time >= time '12:00')
    or (data #>> '{fields,shift}' = 'afternoon'
      and (occurred_at at time zone 'Asia/Taipei')::time < time '12:00')
  );
```
