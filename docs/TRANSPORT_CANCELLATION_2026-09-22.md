# 已發布趟次取消

本批為本機實作與驗證，尚未部署或完成正式真人驗收。

派車頁新增「取消已發布趟次」。具有 `transport_plans.approve`、分支及所有乘員查閱權限，並通過近期同一工作階段 AAL2 的人員，填寫至少 8 字理由後可取消尚未執行的有效發布版本。較新的草稿或駁回不取代有效發布；取消仍指向實際已發布版本。

取消使用獨立且不可改寫的紀錄，保留原計畫、發布決定、草稿、取消理由、伺服器人員／時間及重新驗證證據。取消後原趟次不能再修訂、發布或開始；需要恢復服務時建立新的趟次。乘員需求重新列為待派，不再佔用交通衝突資源，也不再列入接送執行待辦與未取消乘員總數。

任何已有執行 stream 的趟次（包含執行中及已完成）均拒絕取消。現場應在接送執行記錄例外、確認乘客安全及上下車狀態後完成趟次；本批不提供將執行事實抹除的取消路徑。外部通知仍未接通，取消成功後畫面要求安排替代接送並人工聯絡。

取消、計畫版本／決定及開始執行共用趟次交易鎖；取消交易重新檢查目前權限與發布版本。並行、版本衝突與冪等鍵不同內容均拒絕；同人同鍵同內容回原回執。瀏覽器在結果未知時凍結原內容並保留操作鍵，只在嚴格回執通過後刷新。

驗證：

- `transport_trip_cancellation.test.sql`：44 項 assertions；真實 Google/session 入場 fixture、理由、版本、權限、同鍵重播、不可變歷史、較新草稿、派車核對及執行 guard。
- 既有派車 37 項、接送執行 62 項、每日派車核對 45 項 SQL 回歸。
- PostgreSQL 17.11：123 migrations 編譯、44 項取消 assertions；實際雙連線觀察鎖等待，驗證同鍵並行、取消先於開始、開始先於取消、等待車輛鎖期間撤銷乘客個案授權、重送收據等待操作鎖期間撤銷授權五種競態。取消在所有資源鎖取得後依當下時間重新核對每位乘客授權；已撤銷分派者必須回覆 `42501`，不得寫入取消紀錄或讀取原收據；既有取消歷程仍保留。
- API／parser／工作區／取消介面 39 項 Vitest 通過；包含斷線同內容同鍵重送。

原生資料庫驗證使用 `scripts/test-transport-cancellation-native.mjs`，僅在臨時 Unix socket cluster 與合成資料執行，不接受遠端資料庫網址。正式發布前仍須依最新應用基線整合、migration dry-run、正式資料保全與真人人車作業驗收。
