# 個案文件及每週安排補強：實作範圍與驗收

本批從 `dffb20b` 工作基線開始（前一正式應用來源為 `a72079f`，`dffb20b` 只補發布文件）；實作、測試、正式發布分別記錄，不宣稱全部 89 頁完成。

## 現場作業與介面提案

入口為「個案匯入與收案 → 應備文件」及「每週到站與接送」。使用者為已有個案／附件類別權限的機構管理員、護理及相關人員；保留既有 Google／重新驗證界線。畫面與測試一律合成資料。

- 改善前：六類文件同時展開多組欄位，手機需長距離捲動；覆核只對最新一份，歷史最多 200 份。
- 改善後：補件狀態先呈現，上傳欄位按需展開；另有逐份文件清單，可分頁、覆核、補正、停用及重新覆核採用。停用不是刪除或停藥醫囑。
- 歷史採固定查詢快照，標示查詢時間及五分鐘效期，過期需重查；每次後端分頁請求重新驗證授權。已讀頁可在效期內返回查看；新增修改或下載仍重新驗權。
- 不明儲存結果必須保留原操作；確定版本衝突須重新查詢並由使用者重新選擇與確認，不靜默覆寫。
- 每週安排和單日例外共用一個待確認操作；不能在回覆不明時改內容或換一種操作造成新 key。

## 本批驗收門檻

1. 同案兩份藥袋可獨立處置；只改其中一份，另一份、原始檔、既有紀錄不變。
2. 新增或停用文件不自動產生醫囑、給藥紀錄、出勤或正式收案。
3. 同 key 同內容重送只留一筆；同 key 改內容拒絕；兩人同基準修改一成功一衝突。
4. 機構、分支、個案、類別、停權與重新驗證在 API 及資料庫驗證；未授權讀寫、跨個案 cursor 拒絕。
5. 201 份以上歷史可完整查閱；頁面不重複、不遺漏；新上傳不混入既有查詢；快照過期、超出安全上限明確提示而非假裝資料完整。
6. 未掃描、感染、掃描失敗不可下載；已停用乾淨文件只可作歷史文件下載；簽署網址仍短效且稽核。
7. 網路中斷、回條格式錯誤、首次確定衝突、未知後再遇拒絕分開測試；不得因失敗更新基準或遺失另一份草稿。
8. 390px 手機及 1440px 桌面無水平溢出；輸入 16px、控制項至少 44px、鍵盤焦點可見；空資料、讀取失敗、過期、唯讀及待確認均有下一步。
9. 全量 TypeScript／單元／SQL 相容回歸，並用原生 PostgreSQL 檢驗升級及併發；展示／mock 測試不得冒充正式 Storage 或真人流程。
