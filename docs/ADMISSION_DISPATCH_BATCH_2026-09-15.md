# 收案、每日分工與派車對帳批次

本批為 89 頁完整化中的一個切片，不代表所有表單已正式啟用。

## 使用者流程

1. 個案匯入與收案工作台保存資料後，以穩定個案 ID 接到正式收案／異動頁；未存草稿、儲存中或讀回失敗時不得接續。
2. 目的頁重新取得授權資料，只帶入同個案。不依姓名比對、不退回清單第一人、不自動送出。
3. 主管確認生效日期與理由後建立正式異動。每日安排依指定服務日的收案、暫停、恢復與結案歷程判定適用性。
4. 每週安排的去程／回程需求與最新已發布派車逐人、逐日、逐方向比對；顯示待派車、已派車、重複待核對或無查閱權限。

## 本批驗收門檻（完成證據另記）

- 直接網址的無效／未授權個案不得帶入其他人；篩選及分頁保留同一 ID。
- 帶入頁面、保存週表與重新讀取均不產生收案、出勤、給藥、趟次或申報。
- 異動與分工重送固定 body、key、base version；未知結果後即使收到 4xx 仍不得當作已確認未儲存。第一個已知版本衝突須人工重讀。
- 未收案、收案前、暫停期間及結案生效日以後不能新增 scheduled 分工；主管仍能核對並取消原有不適用分工。歷史有效服務日不被當前狀態抹除。
- 派車比對不使用姓名；草稿不算已派車，單日取消需求及最新發布版本移除的乘客不得列已配對。多筆有效匹配明示衝突。
- 欠權限、快照錯誤、缺漏或超限不得顯示假 0；計數與明細使用同一資料庫快照。
- 使用合成資料做角色、版本、並行、API、390px／桌機及返回流程測試。真人 Google 登入驗收與正式服務證據分開列示。
- 機構／分支停用、鎖等待中撤權及停用後延遲重送，正式收案及既有資料均不得再變更。
- 收案與分工未知結果尚待確認時，阻擋工作清單刷新及切分支；更新或切分支先開始時也阻擋新寫入。操作鎖僅為記憶體中的無內容 token，不儲存個資。
- 元件卸載後晚到的確認成功只釋放已完成操作，不刷新其他頁；晚到未知結果不自動解鎖。這不等於跨分頁或強制關閉瀏覽器後的持久化操作復原。

## 保留邊界

不放寬既有正式異動與簽署重新驗證政策；不自行配置付費服務、外傳個資或更改 Supabase 區域。CMS 封存、掃毒、機構採用的正式量表／申報格式仍須獨立完成。現有趟次模型尚無正式『取消趟次』工作流，本批不得把退回草稿冒充取消已發布趟次。
