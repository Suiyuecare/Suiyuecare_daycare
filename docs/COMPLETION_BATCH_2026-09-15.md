## 一致性與保護

- 沿用既有橘／米色介面與元件，不更換平台或新增收費資源。
- 報表入口依來源權限顯示；直接開頁、API 與 SQL 仍各自驗證，不能以隱藏按鈕取代權限。
- 新資料庫函式使用限定範圍的 private helper／public invoker；讀取留稽核，不用 service_role 讀取個案報表。
- 自訂表單採基準 revision、交易鎖與冪等回執。初次儲存已確認的代碼重複可保留輸入改代碼；版本衝突須載入比對，明確確認後才採新基準；不明回覆維持同一 key 重試，不靜默覆寫。先前回覆不明時，即使後續重試因撤權或鎖定被拒絕，也保留原操作直到可核對回執，不誤認先前從未提交。
- 自訂草稿 API 最長等待 10 秒，瀏覽器 20 秒；逾時不代表交易沒有提交，因此保留原重試操作。
- 切換機構、分支、使用者、角色／權限或驗證狀態時，表單工作區重新建立，避免沿用舊草稿 state。
- 臺北時間採固定分隔格式，避免瀏覽器與 Node 的日期空白差異造成 hydration 失敗。
- 報表無公開快取、無離線持久化、無批次下載。月報資料一分鐘後標示過期；斷線不顯示可誤用的新數字。

## 驗證紀錄

所有測試為合成資料。本輪原先的 `/tmp` 工作目錄於環境恢復時已不存在；已從本任務自己的 literal apply_patch 紀錄恢復至持久 worktree，未執行歷史命令或接觸真實個案附件，亦未修改原本有其他變更的工作目錄。

- 復原：40 次 patch、67 個檔案路徑，無未解析動態 patch、無套用衝突。
- 獨立復原覆核：三個子任務共 44 個檔案全數存在，43 個與最後修改逐位元一致，另一個含主任務後續預期的固定時間格式修正。復原後另補上「先前回覆不明、後續撤權」仍保留原冪等 key 的回歸。
- 最終 `pnpm lint`、`pnpm typecheck` 均通過。
- 最終 `pnpm exec vitest run`：398 檔通過、1 檔既有跳過；4,275 項通過、1 項跳過。
- `pnpm test:database`：115 份 migration 編譯通過，111 檔、4,990 項 SQL assertions 通過；其中 93 套為 legacy PGlite fixture、18 套執行完整 admission 條件，不將相容測試冒充正式 Supabase 驗收。
- 原生 PostgreSQL 17.11：115 份 migration；576 項工作流程 assertions、9 項額外 ACL／Storage／索引檢查通過；104→115 migration 升級保留既有合成個案、量測、表單與角色；真實雙連線確認同 key 一筆、不同 key 同基準一成功一衝突、帳號啟用一次。
- `ROUTE_SMOKE_BASE_URL=http://127.0.0.1:3184 pnpm test:routes`：原有 89 個頁面路由／標題煙霧檢查通過，不等同逐頁完整業務驗收。三個新增報表路由另外經元件、loader／API、SQL 與瀏覽器驗證。
- 最終 `pnpm build` 通過。仍有既有 `preferredRegion` 設定 deprecation 警告，未以此推定正式執行區域，部署前另核對平台設定。
- 本機 Finance 預檢在未注入設定時正確列出 5 項缺設定，exit 2、外部請求 0、寫入 0；Node 有既有 package module type 提示，未為消除提示而改整個專案模組模式。
- 瀏覽器以 390px 手機及 1440px 桌面抽驗本批介面；已檢視截圖。收案搜尋後卡片與明細同步 4→1，來源連結到同個案 `profile`；月報 30 天／人次與日期連結正確；自訂表單空白試填被提示、填入合成答案通過且正式儲存停用；Finance 顯示缺設定、不洩漏憑證；最終工作階段 JavaScript errors 0，受測畫面無水平溢出。
- 本機 PostgreSQL 使用可銷毀的 Unix socket 隔離叢集，不接受 hosted URL；Auth／Storage 為合成 fixture，不等於真實 Google OAuth 或正式 Storage 驗收。
- 畫面驗收使用安全展示模式，主動停用所有外部整合與正式寫入。它可證明畫面互動，不證明真人登入後完整寫入流程。
