# CMS 收案工作台：實作與驗收紀錄

日期：2026-09-14。狀態：本機實作；尚未推送、發布或套用正式資料庫遷移。本批未開通帳號、變更角色、建立付費服務或上傳真實個案。

## 操作入口與範圍

新增 `/app/client-intake`，側欄固定顯示「個案匯入與收案」。個案中心、個案基本資料、收案異動與舊中央匯入頁均有入口；仍保留原 89 頁及獨立路由。個案基本資料列的「核對／補充資料」直接帶入穩定個案 ID，舊個案也能接續，不再開啟無法修改新收案版本的舊編輯器。

五個步驟：匯入與建檔 → 基本資料 → 每週到站與接送 → A／B／C 表 → 應備文件。建檔後是「待收案」，不自動開始服務、核准表單或建立給藥執行證據。

| 項目 | 本批實作 | 驗收判準與證據 |
|---|---|---|
| CMS 建案 | 伺服器靜態解析、逐欄確認、版本／來源保留、單一交易正式建案 | 來源不能由瀏覽器偽造；只按精確身分比對；同檔重傳可找回批次；衝突不靜默覆寫；交易失敗不留下半份正式資料。API、SQL、黃金樣本測試。 |

## 設計檢查與前後差異

依介面簡化技能將「治理用解析器」與「現場收案」分開：前者保留來源核查，後者先顯示缺項與下一步。資料雜湊及完整來源細節折疊，主要欄位逐項確認，不用工程術語代替操作回饋。

| 優先度 | 原本阻礙 | 本批調整 |
|---|---|---|
| P0 | 匯入藏在治理頁，解析完成不代表已建案 | 明確收案入口、正式建案交易及個案回讀 |
| P0 | 主檔、週表、表單、文件切散 | 同一個案接續五步；不必再次輸入個案姓名 |
| P1 | 舊編輯器對新版本個案會回含糊權限錯誤 | 清單列統一導向新版補充資料；讀取不因缺少近期重新驗證而藏入口 |
| P1 | 來源資料、排程與已執行照顧容易混淆 | 待收案／預計／草稿／待覆核分開；不假造完成 |
| P1 | 手機表單密集、切換可能遺失草稿 | 390px 單欄，較大畫面分欄；個案選擇全寬，操作目標至少 44px；dirty/busy 保護 |

已使用合成資料檢查 390×844 手機、820×1000 平板與 1440×1000 桌機，未見頁面橫向溢出。檢查涵蓋清單帶案、五步切換、週表、A/B/C 分頁、六類附件、焦點樣式及主要控件尺寸。這不等於完整 WCAG 2.2 AA、螢幕閱讀器或正式登入端到端認證。

## 必須完成後才能正式接收個資

1. 審查及套用四份 migration，先在隔離測試庫完成真 PostgreSQL RLS、交易、並發、既有資料升級及角色矩陣驗證。正式驗收須使用已授權 Google 帳號，不能使用 demo 代替。
2. 完成 Tokyo S3 Object Lock Compliance／KMS／七年封存設定及實際寫入後保留證明。現有網頁代理上傳限 4MB；解析器的 25MB 上限不代表已完成 25MB 網頁上傳，大檔路徑另做。
3. 完成私有 Storage、具有效憑證 TLS 掃毒服務、DPA／次處理者／資料區域與費用審查。以合成檔驗證感染、壞檔、逾時、重傳、下載過期及跨角色隔離，通過後再開真檔。
4. A/B/C 草稿尚需正式範本發布／雙人核准、責任人簽署、官方原稿 PDF 套印、照片／家系圖等真附件連結。不能拿本批草稿當作完成評鑑正式文件。
5. 多份藥袋原檔會保留，但逐份有效／停用與逐份覆核未完成；目前補件狀態依分類最新一份。附件歷史最多顯示最近 200 份，超過的分頁尚未完成。藥袋／歷史文件不會自動變成有效醫囑或本中心給藥紀錄。
6. 核對完整原表欄位、實際派車與需求對帳、正式收案審核、文件缺項阻擋規則及現場角色操作；執行備份／復原與端到端驗收。本批未宣稱達成全系統上線條件。

## 發布順序與回復

先審 migration 與備份 → 隔離環境套用 → 合成完整收案流程 → 確認封存與掃毒成本／供應商 → 明確核准後套用正式 migration 與發布 → 授權帳號現場驗收 → 才啟用真實資料上傳。

若需回復前台，回到上一部署但保留新資料與稽核；不可直接 down migration 刪除收案版本或已封存原始檔。新 intake 個案不能用舊簡化編輯器更新，回復時仍需保留新版資料入口或暫停寫入並公告。
