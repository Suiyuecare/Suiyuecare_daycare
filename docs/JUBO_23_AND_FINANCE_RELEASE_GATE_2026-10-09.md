## 已確認的業務決定

- JUBO 個案主檔應有 23 位；17 筆當月清冊只做精確身分與狀態核對，不再新增 17 位個案，也不將首次服務日當作出勤。
- 23 位若無可驗證的正式收案日與服務資格，顯示「待收案」。管理者可核對、補資料及填評估草稿；在正式收案前，禁止簽署服務紀錄、出勤、給藥、排車及申報。
- 來源狀態須保留：17 位服務中、1 位暫停、5 位結案。系統的「待收案」是新系統作業資格，不得抹掉來源歷史狀態或誤顯示為「服務中」。
- 原始清冊只有 5／23 位具首次服務日，且首次服務日不得推論為正式收案日或出勤。待補欄位須逐項標示來源與缺口，不可自動填入不存在的服務資格。
- 現有個案沒有胰島素需求；沒有真實醫囑、有效資格與雙人覆核的資料證據時，施打功能維持封閉。
- 老闆頁 Finance 萬華店口徑限 J1101／E6，自 2026 年 7 月起依正式帳本唯讀；收入科目 4／7，支出 5／6／9，沖銷及作廢按 Finance 淨額；畫面須標「帳本分錄，非已結帳」。正式啟用前須由具名財務負責人及不同的覆核人簽認逐月金額與來源。

## 2026-10-09 候選進度

- 來源離線解析已辨識 23 筆主檔與 17 筆清冊相符；仍沒有資料庫正式寫入回條或個案中心 23 筆讀回證據。
- 候選 SQL 已增加待收案前檢、來源逐筆覆核與私有隔離名冊；公開 `clients` 寫入仍需可信的「同一原始位元組→解析→暫存→覆核→交易」鏈及完整作業阻擋矩陣，不得放行。
- `pending` 公開個案狀態目前只存在未授權執行的隔離候選；多個工作模組的前端狀態解碼尚按舊五種狀態列舉，其中 SPMSQ 快照可確認會因 `pending` 而整頁讀取失敗。需依各模組實際快照逐一確認影響範圍，不得以搜尋命中數充當故障頁數。活動、餐食的個案 ID 陣列和私有每週排程／附件也未經通用單筆觸發器涵蓋；主管補資料與評估草稿仍未達標。因此不得把候選 migration 套入正式庫或執行 23 筆正式主檔寫入。
- 隔離候選的待收案觸發器會拒絕所有個案更新及多數評估草稿；既有收案寫入與完整題目量表查詢也只接受已收案狀態。另一方面，通用觸發器只覆蓋 `public` 單筆 `client_id`，`private` 自訂表單簽署與 ABCD 送審／核准／匯出等 RPC 仍可能繞過。須先建立同一收案資格閘並直接呼叫 RPC 測試，不能為了讓頁面顯示而直接取消資料庫護欄。
- 日照正式環境目前仍無萬華正式個案；東京平行專案尚未切換為網站正式資料庫。既有首爾合成個案不得刪除或靜默忽略。
- Finance 已有 J1101／E6 同帳本唯讀核算候選，但來源 PR 仍是草稿，缺具名財務簽認、受控發布及真實連線驗收；此處不記載任何實際金額。
- 胰島素醫囑來源與獨立覆核有候選檢查；沒有目前個案需求，也沒有正式醫囑／資格附件證據，仍不可啟用。
