## 已確認的業務決定

- JUBO 個案主檔應有 23 位；17 筆當月清冊只做精確身分與狀態核對，不再新增 17 位個案，也不將首次服務日當作出勤。
- 23 位若無可驗證的正式收案日與服務資格，顯示「待收案」。管理者可核對、補資料及填評估草稿；在正式收案前，禁止簽署服務紀錄、出勤、給藥、排車及申報。
- 來源狀態須保留：17 位服務中、1 位暫停、5 位結案。系統的「待收案」是新系統作業資格，不得抹掉來源歷史狀態或誤顯示為「服務中」。
- 原始清冊只有 5／23 位具首次服務日，且首次服務日不得推論為正式收案日或出勤。待補欄位須逐項標示來源與缺口，不可自動填入不存在的服務資格。
- 現有個案沒有胰島素需求；沒有真實醫囑、有效資格與雙人覆核的資料證據時，施打功能維持封閉。
- 老闆頁 Finance 萬華店口徑限 J1101／E6，自 2026 年 7 月起依正式帳本唯讀；收入科目 4／7，支出 5／6／9，沖銷及作廢按 Finance 淨額；畫面須標「帳本分錄，非已結帳」。正式啟用前須由具名財務負責人及不同的覆核人簽認逐月金額與來源。

## 2026-10-09 候選進度

- 來源離線解析已辨識 23 筆主檔與 17 筆清冊相符；仍沒有資料庫正式寫入回條或個案中心 23 筆讀回證據。
- 候選 SQL 已增加待收案前檢、來源逐筆覆核與私有隔離名冊；公開 `clients` 寫入仍需可信的「同一原始位元組→解析→暫存→覆核→交易」鏈及完整作業阻擋矩陣，不得放行。
- `pending` 公開個案狀態目前只存在未授權執行的隔離候選。SPMSQ、GDS、跌倒風險、NSI、咀嚼、適應、MNA、OT／PT 評估與服務、心理社會、專業摘要，以及服務計畫、疫苗、護理、社工、家屬摘要與收案完整性報表已補唯讀解碼；社工與 OT／PT 正式服務新增選單不提供待收案個案，家屬摘要仍只呈現既有可公開的服務中個案。這是候選解析，不等於真人逐頁驗收或新增正式寫入權限。活動、餐食、指定個案行事曆及正式列印的名單／快照已有候選表層寫入閘與本機測試；私有 ABCD 送審／核准／匯出、自訂表單簽署／列印與外部量表正式結果也已補資料表寫入閘，待收案只能保存允許的私有草稿。五種公開量表（SPMSQ、GDS、跌倒風險、NSI、咀嚼）已有待收案草稿例外，正式簽署仍受阻；原量表回歸 259／259、本機 JUBO 閘測試 208／208 通過。排班與交通草稿的 owner 直接寫入已驗每位乘客存在且屬同機構／分支，並拒絕待收案乘客。正式 PostgreSQL 並行驗證與真人逐頁驗收未完成，因此不得把公開 `pending` migration 套入正式庫或執行 23 筆正式主檔寫入。
- 評估矩陣與其他受治理問卷仍須逐頁核對待收案草稿入口；五種已補草稿例外不代表全部量表已通過。狀態解析清單必須再與所有實際 SQL 來源及角色快照雙向查證，不可把搜尋命中數當作故障頁數。
- 隔離候選的待收案觸發器仍拒絕所有個案主檔更新及正式評估寫入；既有收案寫入與完整題目量表查詢只接受已收案狀態。主任補件及無計分評估準備改用獨立私有草稿命名空間、分支主任狹義權限與新工作台；本機 50／50 項測試通過。草稿結果不明時，可憑原次冪等鍵唯讀查原回條；即使已有較新版本，也不能把原寫入誤判為失敗或自動覆寫。這不會改寫 JUBO 原值或開放服務操作，且未經真人 Google 登入及託管 PostgreSQL 驗收。私有 ABCD、自訂表單及外部量表正式結果的已知寫入繞過已在候選資料庫閘中封堵；不能為了讓頁面顯示而取消通用資料庫護欄。
