# 正式上線門檻

任何一項未通過，都不得把系統標示為正式可營運。

## 帳號與權限

- 員工必須使用已核准、綁定機構的公司 Google 身分及有效工作階段。依產品負責人要求，明確允許的未簽署例行流程（收案建檔、每週安排、ABCD 草稿與題目式量表草稿）不另要求 App 驗證器；API 與 RPC 均須實測相同政策。不得因允許這些 AAL1 草稿操作而移除其他資料表或高風險操作的保護。
- 已核准機構 A 的員工，即使另有機構 B 的 membership、permission 與個案 assignment，也不得自動取得機構 B 的員工開通授權；全機構管理員的獨立核准例外仍須有效的目標機構／分支 membership。
- 高風險操作使用真正的近期第二因子證據，不得只依賴仍有效的舊 AAL2 JWT。
- 組織級與分支級角色不可互相提升；分支主管不能建立組織級 membership 或指派 system role。
- 停用員工 5 分鐘內撤銷所有 session，並實測既有 token 無法繼續讀寫。
- 家屬 OTP 不自動建立帳號；無有效 consent、跨個案與跨資料類別讀取結果均為 0 筆。

## 基礎設施與資料

- 須取得實際區域證據：Supabase 為東京 `ap-northeast-1`，Vercel Functions 為 `hnd1`。
- 正式方案須具備 99.9% SLA、PITR、備份與稽核，並完成 RPO 15 分鐘、RTO 4 小時還原演練。
- S3 啟用 Versioning 與 Object Lock；上傳後以 Head/Get 驗證 Compliance、KMS key、版本 ID、retain-until 及 SHA-256。
- 原始 HTML、API、家屬與機構頁面均為 private/no-store；CDN、log、trace、error 不含明文個資或附件。
- ABCD 重載續做所需的敏感保留內容，須以正式排程在期限後刪除並監測成功／失敗；僅建立 24 小時到期欄位或手動清除函式不算通過。保留操作、續做與直接 RPC 需在正式 PostgreSQL 多連線競態中驗證。
- 所有供應商完成 DPA、次處理者、資料區域、跨境傳輸與資料退出審查。

## 業務完整性

- 89 頁逐頁通過載入、空值、無權限、錯誤、逾時、離線、過期與重試狀態。
- 79 個對等頁完成合法人工功能矩陣；沒有用共用空殼取代頁面專屬流程。
- 用藥、胰島素、高風險藥物、補登與第二人覆核完成正反向測試。
- 意見與申訴的期限規則已由業務正式發布並完成版本治理；高風險／逾期外部升級具有 worker、送達回執與失敗告警，且畫面、事件鏈及正式匯出使用同一快照。未配置任一項時不得宣稱已通知、已匯出或可正式受理。
- 電子簽署由資料庫原子 RPC 產生伺服器時間、內容雜湊、紀錄版本、簽署目的與近期重新驗證證據；不得信任瀏覽器提交的簽署欄位。
- 題目式量表的新增評估、指定草稿修訂、不可變歷程及正式簽署須分開驗收；草稿保存或計分預覽不得標示為正式結果。已取得題目使用授權不等於程式規則啟用、計分及簽署流程驗收通過。
- 題庫完整原文／雜湊、來源與公式固定；規則採用／退休由真人獨立雙人核准，不得由部署 seed 代為啟用。正式簽署在同一分支／量表鎖內核對包含退休的有效期限，人工確認安全警示，不使用新版本回溯重算舊結果。
- Cookie 認證的治理寫入在讀取內容前核對設定來源與 JSON 格式；身份、近期驗證、資料庫權限及冪等檢查不能被來源防護取代。
- 量表直接 RPC 必須拒絕缺漏／NULL 答案狀態、非字串 context 與不合理測量；升級前盤點既有不可變版本，合法既有資料保留，完成新約束的 `VALIDATE CONSTRAINT`。有歷史錯誤時不得靜默改寫或刪除。
- 未保存答案切換畫面須明確確認；未知保存結果固定內容與冪等鍵重試，禁止不明提交期間更換個案／分支。安全登出不能被永久鎖住，也不能在重新登入後留下無法解除的本機操作鎖。
- 申報匯出／回覆對帳、通知投遞、匯入正式欄位提升及更正紀錄均在各自的單一交易中完成，失敗時不得留下部分狀態。
- 畫面、明細、PDF、匯出與申報使用相同不可變快照，數量與金額完全一致。
- Finance 單店讀取須確認實體僅含該店，並驗收真正 hosted HTTP、SQL 取消／重試、真實金額對帳及定時更新；本機合成測試或手動更新不能代替持續即時讀取證據。
- 七年移轉至少兩次完整彩排；關鍵欄位與財務／申報總額 100% 核對，重大差異為 0。
- 至少平行運行一個完整申報週期；重複申報、重大權限／簽署／用藥／資料錯誤均為 0。
