# 正式上線門檻

任何一項未通過，都不得把系統標示為正式可營運。

## 帳號與權限

- 所有員工登入均為 AAL2；AAL1 直接呼叫 Supabase Data API、Route Handler 或 RPC 均被拒絕。
- 高風險操作使用真正的近期第二因子證據，不得只依賴仍有效的舊 AAL2 JWT。
- 組織級與分支級角色不可互相提升；分支主管不能建立組織級 membership 或指派 system role。
- 停用員工 5 分鐘內撤銷所有 session，並實測既有 token 無法繼續讀寫。
- 家屬 OTP 不自動建立帳號；無有效 consent、跨個案與跨資料類別讀取結果均為 0 筆。

## 基礎設施與資料

- Supabase 專案實際區域為東京 `ap-northeast-1`，Vercel Functions 實際區域為 `hnd1`。
- 正式方案已具備 99.9% SLA、PITR、備份與稽核；完成 RPO 15 分鐘、RTO 4 小時還原演練。
- S3 啟用 Versioning 與 Object Lock；上傳後以 Head/Get 驗證 Compliance、KMS key、版本 ID、retain-until 及 SHA-256。
- 原始 HTML、API、家屬與機構頁面均為 private/no-store；CDN、log、trace、error 不含明文個資或附件。
- 所有供應商完成 DPA、次處理者、資料區域、跨境傳輸與資料退出審查。

## 業務完整性

- 89 頁逐頁通過載入、空值、無權限、錯誤、逾時、離線、過期與重試狀態。
- 79 個對等頁完成合法人工功能矩陣；沒有用共用空殼取代頁面專屬流程。
- 用藥、胰島素、高風險藥物、補登與第二人覆核完成正反向測試。
- 意見與申訴的期限規則已由業務正式發布並完成版本治理；高風險／逾期外部升級具有 worker、送達回執與失敗告警，且畫面、事件鏈及正式匯出使用同一快照。未配置任一項時不得宣稱已通知、已匯出或可正式受理。
- 電子簽署由資料庫原子 RPC 產生伺服器時間、內容雜湊、紀錄版本、簽署目的與近期重新驗證證據；不得信任瀏覽器提交的簽署欄位。
- 申報匯出／回覆對帳、通知投遞、匯入正式欄位提升及更正紀錄均在各自的單一交易中完成，失敗時不得留下部分狀態。
- 畫面、明細、PDF、匯出與申報使用相同不可變快照，數量與金額完全一致。
- 七年移轉至少兩次完整彩排；關鍵欄位與財務／申報總額 100% 核對，重大差異為 0。
- 至少平行運行一個完整申報週期；重複申報、重大權限／簽署／用藥／資料錯誤均為 0。

## 品質與營運

- 5 分支、500 個案、200 員工、50 並行使用者下，一般讀取 p95 ≤ 2 秒、寫入 p95 ≤ 1.5 秒。
- OWASP ASVS Level 2、自動弱掃、相依套件掃描及正式上線前第三方滲透測試通過。
- WCAG 2.2 AA 自動與人工鍵盤／螢幕閱讀器／390px 驗收通過。
- 重大錯誤 5 分鐘內偵測、15 分鐘內值班確認，告警與追蹤內容不含個資。
- 備份還原、供應商故障、LINE webhook 重送、SMS failover 與斷網同步演練通過。
