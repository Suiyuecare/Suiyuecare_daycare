## 測試證據

凍結後實際執行；私有測試輸出、原始來源、截圖與 Vercel manifest 不進公開 repo。

- 完整 Vitest：538 檔、6,032 項全過、無跳過；本機另注入已授權的私有 JUBO 來源路徑及 Finance 唯讀合約路徑，沒有 hosted 寫入。
- Node 工具契約：147／147，無跳過；包含東京設定 30 個、Finance 原生 CLI 6 個及 HTTP 負載工具 13 個契約。工具測試不是正式連線或實際 50 人負載。
- 完整 PGlite：146／146 套件、6,833 項全過；其中 92 份是凍結的舊本機准入 fixture、54 份不覆寫准入判定。不可拿舊 fixture 套件當真人登入或原生 RLS 證據；重要邊界另外以原生 PostgreSQL 驗證。
- Native PostgreSQL 17.11：170／170 migration 編譯、14 份不覆寫正式准入判定的套件、886／886 assertions，45 組實際觀察資料鎖等待的競爭／撤權／重送情境。隔離 cluster 僅 Unix socket，runner 已停止；無 hosted 連線。
- 新 Full MNA 候選套件 72 項與獨立發布／簽署套件 28 項，已納入原生上述總數，不另外相加。後者真正以兩個不同的合成使用者及同 session 驗證，測試未發布／待核定／自行核定／AAL1／舊因子／另一 session 拒絕，以及核定後簽署、來源 hash、歷史與 29.5 分精確讀回。
- 本機合成路由 89／89；390px／1440px 的 20 項頁面／尺寸、4 項 MNA 6／18 題及 2 項已存表單檢查通過。未接真實身分或正式附件；不等於 89 頁真人完整作業。
- ESLint（0 警告）、Next 型別生成／TypeScript、正式程式 build、`git diff --check` 通過；相依套件 audit 未發現已知弱點。
- Vercel dry-run 來源 manifest 通過：禁止檔案、符號連結及已知秘密字面值皆 0；沒有建立或提升 deployment。此為有界來源檢查，不是通用個資／秘密偵測證明。

## 測試中查明與仍未查明的問題

- 自訂表單 SQL fixture 在新 challenge 建立後仍使用 transaction-start `now()` 作為 JWT `iat`。當前面的測試花費超過兩秒，正式守門正確拒絕過舊 JWT，後續恢復 fixture 時才出現 NULL `verified_at`。已刷新合成 JWT 發行時間，並新增「早於 challenge 的 JWT 必須拒絕」的固定負向測試；正式守門一行未改。
- ABCD A 表的 jsdom 單一拒絕恢復測試隔離跑約 4.5 秒、全套曾超過原 5 秒。僅對該大表單測試採與相鄰測試相同的 15 秒有界預算，保留所有拒絕、狀態、欄位與按鈕斷言；不宣稱這是瀏覽器效能改善。全量來源核對測試另將 MNA 矩陣舊 9 格預期改為 10 格，並明確檢查 SF／Full 都是獨立草稿。
- 第一個完整 PGlite 執行曾在 `google_aal1_scoped_assessment_reads.test.sql` 的身體觀察簽署找不到匹配的驗證 challenge；當時未捕捉匹配條件，後續沒有重現，根因尚未確認。已增加受限的合成布林診斷與原生 PostgreSQL 套件；失敗時仍拋原 42501，不轉成功、不跳過。這與上述已查明的自訂表單 JWT fixture 問題分開記錄。
- 全站 premium 靜態檢查有 719 條 findings（297 條原生控件 ownership、422 條表單／文字區域啟發式規則，包含測試 fixture）；不是 719 個已確認產品 bug，亦未逐條完成全站審核。既有 `UX-CONTRACT.md` 接受原生選單／日期，靜態工具沒有讀成 ownership metadata；本次沒有完成全站人工 WCAG、跨瀏覽器或 89 頁真人操作驗收，不把合成瀏覽器檢查冒稱全站合格。
