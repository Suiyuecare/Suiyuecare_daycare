## 1. 成功的定義

員工不需要先認識 11 個模組，就能知道「今天照顧誰、還缺哪一步、現在按哪裡」。

保留使用者指定的 Finance 外框、字型與品牌配色；改變的是資訊優先順序與操作方式，不另做品牌。89 個原定工作頁面與獨立入口保留，常用工作改由捷徑進入，全部功能仍可找到。不因画面簡化而刪除功能、改權限、改官方題目或解除安全門檻。

## 3. 全系統共用原則

1. 一個畫面只有一個最醒目的下一步；危險或低頻操作放次要位置。
2. 圖示搭配短文字，不用只有圖示、顏色或動畫才能理解的狀態。
3. 一般說明最多一行；補充資訊按需展開。完整題目、必要選項、欄位錯誤與風險告知不受字數限制。
4. 缺值、不適用、未量測、正常、異常各自保存；不能為了整齊把沒有資料變成正常或 0。
5. 操作動詞一致：開始評估、儲存草稿、簽署、補件、下載、核對保存結果。不能用「完成」混稱以上不同階段。
6. 每筆記錄有清楚的本人／個案／日期／班別，不靠同名或最後使用的個案自動猜選。
7. 資料不足、沒有權限、無符合結果及連線失敗，不能都呈現為空名單。
8. 高頻操作不反覆彈確認；用藥、簽署、覆核、捨棄草稿、權限及不可逆操作仍依原規則確認。
9. 不能用「一鍵全部正常」、複製前次答案或自動簽署來降低點擊數。
10. 儲存／掃毒／覆核／正式完成分開顯示。已送出未知結果不得冒稱失敗，也不能另建新操作。

## 4. 導航與角色入口

左側維持 Finance frame，常用區初始顯示四個工作入口與「全部功能」，不先展開全部模組：

`今日工作 → 個案 → 評估與文件 → 交班與追蹤 → 全部功能`

這是工作捷徑，不是合併或删除原頁面。治理、報表、財務等從各角色常用入口或全部功能進入；保留既有深連結。行動版以精簡頂列、常用導航與可操作的完整選單呈現，不能把桌機長表格縮小塞入手機。

| 角色／工作情境 | 登入後優先呈現 | 不預先塞進首頁 |
|---|---|---|
| 照服員 | 已指派的當班個案、量測／照顧待辦、交班事項 | 申報、財務及工程設定 |
| 護理人員 | 今日用藥、量測異常、待第二人覆核、護理評估 | 社工案件與營運管理長清單 |
| 社工人員 | 收案待補、到期評估、服務與轉介追蹤 | 給藥執行表與工程設定 |
| 主任／單點管理員 | 今日到站、未指派工作、逾期與待覆核 | 每位個案全部歷史 |
| 全機構管理員／老闆 | 所選店出勤、收入、支出及來源時間 | 臨床個案內容與不必要的圖表 |
| 駕駛 | 今日接送順序、上下車狀態、例外回報 | 完整健康病史 |
| 專業人員 | 其授權個案的評估、服務與照會 | 非本人權限的記錄 |
| 財務人員 | 收款、帳單、申報／對帳待辦 | 不必要的敏感健康欄位 |
| 系統維護 | 整合健康、失敗工作與稽核 | 預設明文個案內容 |
| 家屬／關係人 | 已授權摘要、行程、訊息與帳單 | 未授權資料及其他家屬訊息 |

主任兼任護理／社工時，捷徑可依已授權工作合併去重；切換工作視角不是取得新權限。實際頁面與 API 仍依現有開通、職務、分支與個案指派重新授權。

## 5. 七個主要工作流

| 工作流 | 預設畫面 | 主動作 | 次要內容 |
|---|---|---|---|
| 今日工作 | 日期／班別、待辦短摘要、授權當班名單 | 每位個案顯示一個下一項工作入口 | 完整分工、來源与時間詳情 |
| 個案中心 | 搜尋、服務中／待收案等快捷條件、名單 | 開啟個案 | 完整篩選、管理統計、歷史 |
| 評估量表 | 個案／日期／評估者列，接著直接呈現題卡 | 儲存草稿；具備正式能力時才簽署 | 計分規則、來源及歷史版本 |
| CMS 收案 | 基本資料、每週到站、交通、評估、文件的步驟與待補標記 | 當前步驟唯一下一步 | 原始映射、雜湊、封存與稽核詳情 |
| 用藥與覆核 | 同一個案／藥物／劑量／時點及執行狀態 | 記錄或獨立第二人覆核 | 原醫囑、歷程、來源；關鍵用藥資訊不可折疊 |
| 交班與追蹤 | 個案、事項、負責人、期限與處理狀態 | 處理／回覆 | 完整處置時間軸；閱讀不等於結案 |
| 店務摘要 | 所選店、期間、出勤與 Finance 收入／支出 | 查看對應明細 | 完整對帳與財務來源詳情 |

### 今日工作的示意結構

以下是文字線框與合成內容，不是新前台截圖或真正的工作紀錄：

```text
今日工作          [今日日期]  [上午] [下午]
[搜尋姓名或代碼                          ]
[待處理] [已完成] [需留意]

測試個案 01 · TEST-001
出勤：已到站   量測：待量測   日誌：未填
                                  [開始量測]

測試個案 02 · TEST-002                需留意
出勤：已到站   量測：已有紀錄  日誌：草稿
                                  [繼續日誌]
```

三格只表達各項作業狀態，不代表所有照顧工作或簽署已完成。今天排程無法取得時顯示「今日安排未取得／請確認」，不能把全部在案名單當成今天應到名單。

### 量表像易填的表單，保留完整正式內容

- 最上方：個案（姓名＋代碼）、評估日期、評估人員。執行／簽署人綁本人登入；不得用任意選單冒用他人簽署。
- 單選：可點整張選項列；多選：明確方框；有限離散分數用數字選項，不採容易誤滑的滑桿。
- 質性記錄用充分高度的文字欄位；必要時提供展開，不把完整輸入壓成一行。
- 每題完整原文、選項與單位仍可讀；不預選答案或正常值。只有既有正式契約允許時才顯示不適用與原因。
- 以「已答／不適用／未填」短摘要呈現進度；缺答不計為 0 分，候選試算不得顯示成正式分數。
- 少量題目採整份自然捲動，長表依原章節分區；不強制每題換頁。手機保存控制不能遮住輸入或鍵盤。
- 尚未具正式能力的量表維持「草稿／尚不可簽署」短標籤；詳細原因可展開，不能把限制藏掉後顯示假的完成。
- 帶入的日期或本人評估者是可確認的表頭資料，不代表題目自動作答。CMS 不得自動生成已完成的臨床評估。

### 文件以分類與狀態卡呈現

身分證、藥袋、用藥計畫、給藥紀錄、體檢各有一張分類卡，顯示文件份數、缺件／待檢查／待覆核／已覆核及下一步。不是只顯示最新一份就代表多張藥袋全已完成。

原檔未經安全處理時用類型圖示，不直接嵌入 HTML、iframe 或外部圖片。預覽功能另列安全相依工作；沒有預覽能力時只提供安全下載與短提示，不畫出可按卻無功能的假縮圖。

## 6. 文字與狀態規範

| 現場不應先讀的內容 | 一般畫面短提示 | 詳情保留 |
|---|---|---|
| 候選計分規則、版本與 hash | 草稿／尚不可簽署 | 題庫來源、計分及正式能力門檻 |
| 冪等原操作／寫入狀態 | 保存待確認 ＋ 核對保存結果 | 原操作定位及稽核證據 |
| 有回條但清單未核對 | 已保存，清單待更新 ＋ 重新讀取 | 精確版本差異 |
| 附件掃毒與供應商設定 | 待安全檢查／目前不能下載 | 掃描狀態、管理處理方式 |
| Finance gateway 錯誤與映射 | 收支尚未更新 ＋ 更新資料 | 同店映射、來源時間與對帳 |

只有已確認且符合該作業定義的狀態才能出現勾選／已完成。無資料以「—／未取得」表達，不補 0；未讀、已讀、確認、處理完成各自區分。

無法作業的原因與可做的下一步不得只藏在問號或 hover 內。一般背景說明整併到一個詳情入口；多個真實風險不可為達文字數目而省略。

## 7. 共用元件與視覺依據

以下是重用／改善的目標，不是另建立一套元件。找不到適用的現有 owner 時，先確認共用責任再寫程式。

| 能力 | 已有依據／優先重用者 | 規劃責任 |
|---|---|---|
| 字型／色彩／圓角／尺寸 | globals.css、DESIGN.md | 保留 Finance frame；不手寫各頁獨立配色 |
| Header／左側選單 | AppShell | 幾何不另造；工作捷徑與全部功能可發現 |
| 選案卡 | ClientSelectionCard | 所有工作流一致識別及切換保護 |
| 同個案接續 | client-continuation、dailyWorkflowHref | 固定個案、日期與班別，不重選、不串案 |
| 今日清單 | TodayWorkList | 短狀態、班別清楚、同人只列一次 |
| 表單 | questionnaire-assessment-editor 與各正式 schema | 題型呈現改進；不改原題、答案及公式 |
| 提示／確認 | inline status／alert、GovernanceDialog、useUnsavedChanges | 一致文字、焦點、失敗與未保存保護 |
| CMS 上傳 | CmsUploadControl | 真實階段、同原操作重試，不假造百分比 |
| 附件 | ClientDocumentsWorkspace、DocumentHistoryPanel | 類別摘要與逐份記錄分開 |

維持目前單一 runtime token 來源。正文舒適可讀，輸入至少 16px、主要觸控區至少 44×44px；標題、粗細、間距及內容卡沿 Finance 既有層級。選中左側項目保持清晰白字及足夠對比，不能為像素相同犧牲可讀性。長機構全銜可換行，不省略成無法識別的縮寫。

初期沿用已文件化的原生日期／選單例外，接受作業系統 popup；不承諾 popup 與 Finance 完全相同。需自訂搜尋選案或日期 popup 時另列共用元件與鍵盤／手機驗收，不隨頁手工拼裝。

不是先改完 89 頁才讓人看，也不把「畫面可點」當功能可上線。逐個完整工作流發布，可回退其 UI，不能回退權限或資料安全修正。功能尚未完善的頁面列相依工作，不以解除停用狀態假裝完成。

## 9. 驗收：以新人能完成工作為主

先測現版，再測原型／候選，任務與合成內容等價。主要測試組 10 位：照服情境 5、護理 2、社工 2、主管 1；另由老闆驗收店務摘要。可用代表角色測試者，不要求為試驗開正式帳號。先不教學，記錄時間、誤點、求助與狀態理解；首次任務採交錯分組，以避免先做舊版造成學習偏差。以下是初始放行目標，未達就修正，不宣稱已達標。

| 指標 | 目標／測量方式 |
|---|---|
| 知道下一步 | 10 人中至少 9 人，看代表卡片 5 秒內說對下一步與是否已簽署 |
| 找到個案／工作 | 至少 9 人，15 秒內找到指定班別、指定個案入口；不得錯人或錯班 |
| 首次任務成功 | 至少 9 人，在無講解下完成其角色的 3 個代表任務，無旁人代操作 |
| 少操作 | 選定個案後，高頻單筆工作原則上 3 個主要動作內到保存；逐題作答、必要臨床核對、第二人覆核不算可刪掉的點擊 |
| 輸入時間 | 給定合成量測值後，至少 9 人 60 秒內保存單笔量測；不把实际量測或臨床評估時間算入 UI 指標 |
| 真正減少文字 | 在相同非異常狀態、相同任務內容下，今日工作與個案中心的預設說明文字較基線至少減半；不刪正式題文、風險或必要識別 |
| 草稿不誤認完成 | 全部測試者分辨未填、草稿、待簽與已簽；任何誤認即阻擋放行 |
| 紀錄正確 | 零錯個案、日期、班別；零重複提交、靜默覆寫或跨權限資料 |
| 手機可用 | 390px 無整頁橫向溢位，16px 輸入、44×44px 主要觸控；鍵盤不遮住目前欄位與動作；桌機及 200% 放大另驗收 |
| 載入清楚 | 每次操作即時給忙碌反饋且不移動按鈕；慢讀取、離線、逾時、未知結果均有短狀態与有效下一步；不得無限轉圈 |
| 效能 | 既有 50 人並行目標維持：一般讀取 p95 ≤2 秒、寫入 p95 ≤1.5 秒；上傳／掃毒另量測其實際階段，不以動畫速度冒充效能 |
| 文件可查 | 所有測試文件顯示實際狀態、份數與版本；通過安全與授權條件的文件可下載，到期可更新；失敗不再重傳已保存檔 |
| Frame 一致 | 同裝置、同字型載入條件比對 Finance 核准基線：header／sidebar、字級、粗細、圓角、控制高度與位置；必要無障礙例外明示 |
| 可及性 | 自動檢查加鍵盤、焦點、閱讀器及觸控人工驗收；顏色／圖示不是唯一意義來源 |

錯人、錯日、假成功、草稿被誤認正式完成、權限外洩與用藥覆核錯誤均為零容忍；不能用平均分數抵銷。
