## CMS 自動提醒怎麼運作

1. 上傳中央 HTML，只做靜態解析，不執行其程式、不載入外部內容。
2. 解析預覽提供「待確認」建議，不當作正式照顧指示。
3. 可信封存批次由授權人員核對穩定個案 ID、確認同一個案並填理由。程式從伺服器保存的可信來源產生候選，不採用瀏覽器自行傳來的臨床內容。
4. 授權人員逐筆發布／不採用；已發布項目才出現在個案接續工作。
5. 新來源提醒重新核對，不自動覆蓋舊照顧計畫。

第一版只有四類：進食、移位、如廁、溝通協助。提醒內容要求依現行核准計畫核對，不自動診斷、改飲食質地、改藥量或執行照顧決策。未知值、只有數字、衝突與缺值都不猜測。

三份使用者原始 HTML 在本機唯讀驗證：40／41／42 區段，均可產生候選，外部請求皆為 0。未把真實檔案、姓名、來源路徑或其他個資放入程式庫；正式測試只保留匿名手寫欄位 fixture。

## 離線與儲存的細節

- 「僅存本機」「待送」「需人工確認」「伺服器確認儲存」分開顯示。裝置草稿不是正式紀錄。
- 結果未知（例如伺服器已寫入但回覆遺失）時，原內容和操作鍵固定，表單鎖定；重開或重試不另建一筆。
- 跨分頁使用鎖與加密版本比對；舊分頁的送出結果不能刪除或覆寫另一分頁的新稿。
- 瀏覽器不支援必要儲存保護時，明確拒絕本機保存，不靜默降級。AES-GCM 裝置加密不是對遭入侵裝置或同源惡意程式的完整防護。
- 登出立即移除敏感畫面，清草稿、清分支及撤銷登入並行；任何一步未確認即顯示重試／清本站資料提示，不宣稱成功。
- 原始 HTML、用藥簽署、財務、申報與權限管理未加入離線範圍。

## 介面驗收

依 UI 簡化 skill，把「今日工作、下一個可操作動作、未完成原因」放在前面；技術名稱保留在管理／文件，不降低後端權限。沿用既有色彩與 frame。

- 1440px 與 390px 比較截圖：今日工作從在案清單改為分支當班清單，加入班別及待指派篩選。
- 新舊示範統計分母不同：新清單 3 位當班個案，不以舊 6 位在案個案冒充應到人數。
- 手機日誌獨立捲動內容區；儲存按鈕與標題固定，欄位原生必填提示仍可操作。
- 實際 Chromium：加密記錄無明文 payload／個案 ID／合成測試內容；重整可恢復；他人命名空間為空；離線儲存 0 次送出、重連 1 次送出後移除；過期稿拒絕；另一分頁登出後表單及合成內容均移除。
- 瀏覽器離線驗收使用明示的合成回執替身，不當作正式 API／資料庫成功證據。真實 SQL/RPC 邊界由本機 PGlite 測試另行驗證。
